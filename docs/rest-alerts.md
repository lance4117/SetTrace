# 休息提醒与剩余组跳过

## 训练状态

组分为待完成、已完成、已跳过。完成两组后跳过两组仍保留目标四组，
历史摘要显示“2 / 4 组完成”；跳过不记录完成时间，不增加统计。
明确修改本次目标组数是另一种操作。跳过只作用于已有完成组的当前动作，
取消当前组间休息并直接进入下一待练动作，不开启动作间休息。

跳过确认和撤销确认都固定对象与训练基线，旧确认不覆盖最新进度。
独立撤销最近跳过按持久化批次恢复，保留后续已完成组与顺序；
撤销上一组只处理真实完成。含跳过组的动作先恢复后才能编辑配置。

## 提醒事件与输出

SQLite 是唯一训练和提醒状态源。每场当前休息关联一个 rest_alerts ID，
调整截止或待练文案增加 revision；系统 Intent 只携带 ID/revision。
Android 投递前验证会话、当前逻辑休息、目标、偏好与 revision 并原子消费。

| 操作 | 数据状态 | 系统副作用 |
| --- | --- | --- |
| 完成一组且配置非零休息 | 保存截止并产生 pending 事件 | 按能力安排精确/非精确唤醒 |
| 加减时间但仍有剩余 | 同一事件更新截止与 revision | 替换旧调度 |
| 换序/换语言 | 更新目标/文案及 revision，截止保持 | 更新未发送内容 |
| 自然到期 | 页面退出休息；事件可消费一次 | 前台短音与视觉提示，后台通知 |
| 跳过休息/减到零/撤销/跳过组/结束/关闭开关 | 事件 cancelled 并增加 revision | 取消旧 Alarm 及已展示通知 |
| 重开时已到期 | 未消费事件 expired | 不补播、不发送旧通知 |
| 回调迟到超过 30 秒 | expired | 丢弃旧提醒 |

Android 原生桥沿用 MethodChannel，独立接收器不启动 Flutter 引擎，
不执行数据库迁移，不回写训练进度。前台计时观察与系统到期回调共用
一次消费入口，不各自播放音频。原生保存数据库路径及系统调度 ID，
其记录只是投影，不代替数据库状态。

训练事务先提交，系统调度在提交后进行。调度失败时组和倒计时保留，
单独显示“提醒安排失败，训练已保存”，可重试。取消 API 失败也不能
复活已失效的事件；重新对账可清理系统投影。

## 设置与系统能力

偏好默认开启，启动时不立即请求权限。首次真正休息时解释通知用途；
拒绝后不会每组重复询问，可从设置跳转系统通知设置。
Android 13+ 后台通知需要 POST_NOTIFICATIONS。较新系统准时提醒使用
SCHEDULE_EXACT_ALARM 的用户设置授权，可选，不使用 USE_EXACT_ALARM。
授权不足使用系统非精确提醒并明确可能延迟；超过 30 秒的旧提醒丢弃。
提醒权限与训练数据恢复是不同能力，拒绝不影响前台训练。

关闭提醒的偏好和事件取消在同一 SQLite 事务保存；保存失败保持原选择。
重新开启只安排未来仍有效的休息，不重置倒计时。语言变化只更新未来
通知文案，用户动作名不翻译。

声音为随应用打包的 300 ms 双音提示，音量与勿扰/静音/通知渠道设置
由系统决定；前台还检查渠道是否至少为有声等级，静默/禁用渠道只保留视觉反馈。
不持续响铃、不请求绕过勿扰权限。不承诺强行停止应用、
手机重启或厂商强制限制后的送达；普通后台、锁屏为验收场景。

至多一次以消费记录先写、声音后输出实现。若进程在两者之间恰好终止，
可能漏提醒，重启不会重复补播；不承诺该崩溃窗口的恰好一次。

## 通知导航与验收

点击只用会话身份读取最新进度，复用已有对应训练页；已结束、丢弃或
不存在的目标显示失效反馈，不打开另一场训练、不创建会话。
冷启动等待数据库、语言和导航就绪再处理点击。

自动测试覆盖迁移、跳过/撤销/换序、提醒修订/竞争/失败/权限与历史统计。
Android 验收记录见 [验收文档](qa/rest-alerts-and-skipping-acceptance.md)。
正常精确模式以截止后五秒内送达为目标，三十秒是失效边界而非准时目标。
