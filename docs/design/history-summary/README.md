## 1. 已确认的设计

解决原四宫格中长时长被拆成“3 小时 12 分 / 钟”、同排卡片高度不一致的问题，同时保留用户熟悉的“统计在上，月份与记录在下”的阅读顺序。

页面从上至下固定为：

1. 页面标题“训练记录”。
2. 两张并列次数卡：“本周训练”“本月训练”。
3. 一张通栏月度汇总卡。
4. 最近训练摘要。
5. 月份切换：上个月、当前所选月份、下个月。
6. 按日期排列的训练记录，或对应月份空状态。
7. 既有计划／记录／设置底部导航，记录为选中态。

**月度汇总卡位于最近训练和月份切换上方。月份标题下直接展示训练记录，不再插入统计卡。** 早期“月份下面放汇总卡”和“紧凑四格”都是未采用的探索方案，不指导后续实现。

## 2. 通栏汇总卡

| 区域 | 呈现 |
| --- | --- |
| 卡片标题 | 当前所选月份＋“汇总”，中文示例“2026年10月汇总” |
| 时长标签 | “训练时长” |
| 时长数值 | 数字突出、单位次要，示例“3 小时 12 分” |
| 下方横行 | 左侧“完成组数”，右侧“63 组”；与时长间使用低强调分隔线 |

卡片是信息展示，不新增点击、展开、累计时长切换或其他操作。标题中的月份始终与下方月份选择器一致，明确统计对象，避免用户将其理解为所有历史累计。

“3 小时”和“12 分”各为完整的数字／单位单元。通常同一行排列，空间不足时允许整单元换行并增高；不能把“小时”“分钟”拆开，不能仅把最后一个字挤到下一行。不能用 `3:12` 替代，避免与休息倒计时混淆。

## 3. 统计口径与月份联动

沿用当前业务与数据模型，不新增统计字段或数据库迁移。

| 指标 | 数据范围 | 切换所选月份时 |
| --- | --- | --- |
| 本周训练次数 | 当前自然周，周一开始；同日多次分别计数 | 保持自身口径 |
| 本月训练次数 | 当前自然月 | 保持自身口径，不能改为所选月次数 |
| 汇总卡训练时长 | 所选月份仍存在的已保存训练时长合计 | 同步更新 |
| 汇总卡完成组数 | 所选月份真实完成组数，排除跳过与未完成 | 同步更新 |
| 最近训练 | 全部已保存训练中，按现有结束时间排序规则确定的最近一次及其单次时长 | 保持自身口径 |
| 记录列表 | 所选月份的已保存训练 | 同步更新 |

本次讨论中的“总时长”指**所选月份合计**，不新增“所有历史累计训练时长”。次数、日期归属、单次时长、快照、排序与删除后的重算规则沿用既有规格。

切月时汇总标题、时长、组数与列表使用同一所选月份。所选月为空时，该月汇总归零并显示月份空状态，本周／本月次数和最近训练不随之清零。全部历史为空时各项按既有规则归零，最近训练显示暂无。

原有初始加载、读取失败、刷新与重试、删除后保留月份、删除成功但刷新失败及防止过期请求恢复旧记录的规则保持。不得为了套用空白草图而将失败伪装成零数据。

## 4. 视觉、字号与适配

- 沿用主规范的语义颜色、四主题色与 16 dp 卡片圆角；草图使用石墨主题色，不能因此把实际应用固定成石墨。
- 页面内距沿用通常 22–24 dp、紧凑屏按实际空间调整的规则。次数卡同排等宽、对齐；卡片高度由内容决定，不固定截图尺寸。
- 标题沿用 28 sp；次数数字约 30 sp，月度时长数字约 32 sp，汇总标题与标签／单位约 14 sp，完成组数约 20 sp。这些是相对层级的设计参考，随系统字号缩放，不是锁定像素。
- 月度卡与次数卡间距约 12 dp，最近训练与卡片约 16 dp，月份区域与最近训练约 24 dp。后续 Flutter 使用既有间距体系映射，不直接照搬浏览器像素。
- 数字使用等宽数字特性，数字与单位按基线排列；单位保持可读对比度。长时长完整可读，必要时按单元换行。
- 覆盖 360／430 dp、字号 1.0／1.3／1.6、中文与英文、浅深主题；窄屏与大字号允许摘要和元数据换行。内容可滚动，底部导航与安全区不遮挡最后一条记录。
- 月份箭头触控区域至少 48×48 dp，保留当前语言的辅助名称。读屏应将时长读成完整语义，如“训练时长，3 小时 12 分钟”。
- 英文月份、单位和动态文案继续使用现有资源与格式化层；不得通过中文字符串拼接或禁用系统字体缩放实现布局。
- 草图中的线性图标只示意语义；Flutter 沿用现有 Material 图标、主题、选中态与导航行为，不新增图标依赖。

## 7. 后续工作范围

本增量仅调整记录页 UI 与适配。通知兼容、HyperOS 后台行为、详细日志及日志导入导出由用户安排到下一项任务，不在本增量中展开。既有计划与完整备份的导入导出保持原范围。

实现涉及的主要职责是 `lib/features/history/history_page.dart` 的布局与 `lib/l10n/` 的呈现文案；`history_stats.dart` 的统计含义保持。开发时应先读取本目录与上层设计入口，再按用户授权进入相应规划／实施阶段。

## 8. 实施映射与时长格式（2026-10-23）

用户已授权实施 `refine-history-summary-layout`。实际结果与待验项目集中记录于
[独立验收记录](../../qa/history-summary-layout-acceptance.md)，不扩大第 5–6 节草图证据的范围。
变更于 2026-10-23 经用户确认同步主规格后[归档](../../../openspec/changes/archive/2026-10-23-refine-history-summary-layout/README.md)，保留 12/13 任务状态及真实 TalkBack 待验项。

`AppFormats.durationParts()` 提供按秒推导的显示分量，数字使用当前语言数字格式；
小时不对 24 取模，不足一小时仅显示分钟，整小时保留零分钟。中文显示“3 小时 12 分”，
英文显示“3 hours 12 minutes”；单位由 ARB ICU 数量规则提供。
`HistorySummaryCard` 用一个 `Text.rich` 保持每个数字与完整单位同基线、不拆行，
由 `Wrap` 在单元之间换行。卡片没有固定高度，不缩小字体或关闭系统缩放。
组数标签与完整数量在宽度不足时上下重排；紧凑页面使用 16 dp 水平内距。

辅助技术只接收一次完整时长消息，中文为“训练时长，3 小时 12 分钟”，
分层数字和显示单位排除重复语义。列表、最近训练与详情继续调用原有
`AppFormats.duration()`，输出的完整分钟单位与既有复数格式保持。
