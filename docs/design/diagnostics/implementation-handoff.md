路径从项目根目录计算，下表保留设计要求，以下“实施对应”说明实际落点。

| 位置 | 当前职责 | 实施约束与对应 |
| --- | --- | --- |
| `lib/features/settings/settings_page.dart` | 外观、语言、提醒、数据入口、关于 | 保持完整设置，数据同卡片增加诊断行；入口已独立于onBackup可用性 |
| `lib/app/app.dart` | 应用状态和导航协调 | 独立诊断路由及来路，返回恢复设置位置；不改既有训练、通知及备份导航含义 |
| `lib/core/widgets/app_card.dart`、`app_button.dart`、`app_task_layout.dart` | 单层分组、按钮和任务页 | 复用现行组件，深层无一级导航，正文与操作区分离；不复制截图固定高度 |
| `lib/app/theme/app_theme.dart`、`theme_color_preset.dart` | 语义颜色及四主题色 | 沿用主题、警告和失败配对；正式品牌资产不随主题色染色 |
| `lib/l10n/` | ARB、本地化和格式 | 新文案与状态进入正式两语资源；时间、单位和完整文件名可重排 |
| `lib/main.dart` | 初始化业务数据库、偏好并启动正常应用 | 独立Bootstrap在数据库打开前呈现，失败进入L07；诊断服务和导出不以业务数据库成功为前提 |
| `android/app/src/main/kotlin/com/settrace/settrace/MainActivity.kt` | 注册文件、提醒等平台桥接 | 保留Flutter插件初始化并增加独立诊断桥；Application级运行时不依赖业务仓储就绪 |
| `PlanFilesBridge.kt`、`BackupFilesBridge.kt`（同上目录） | 已有Download文件写入与生命周期处理 | 可借鉴待发布、重名、关闭、核验和失败清理；不能直接复用计划JSON的2 MiB上限或完整备份的活动训练限制 |
| `lib/features/about/`及现有隐私文案 | 关于、首次说明及版本化说明 | 准确增加本地诊断、分享及清空边界；是否提升说明版本依既有说明规则在技术规划中明确，不改造成自动上传 |

实施对应：`DiagnosticsClient`负责有界Dart观察，`DiagnosticEngine`／`DiagnosticStore`负责应用级原生写入与策略，`DiagnosticExportCoordinator`负责流式打包及公共发布。`DiagnosticsController`消费确认状态，`diagnostics_pages.dart`实现L01–L06／L08、LD01和LE分支；`main.dart`的独立SetTraceBootstrap提供L07。设置同卡片两行已接入，备份不可用仍可进入诊断；返回显式恢复入口焦点。

## 3. UI需要的状态契约

界面通过DiagnosticsOverview／DiagnosticExportStatus与可注入DiagnosticsController消费结果，不直接读取日志文件、解析堆栈或判断业务事务成功，表达：

| 数据组 | 必须能表达的信息 | 不能合并的状态 |
| --- | --- | --- |
| 记录偏好 | 实际确认值、保存中、保存失败及重试目标 | 界面预期值与已保存值 |
| 日志概况 | 加载、可用、读取失败；可读字节、上限、真实起止、缺口、记录受限原因 | 无操作日志与读取失败；存储达到正常清理上限与写入失败 |
| 详细诊断 | 关闭、开启提交中、有效结束时刻、关闭中及失败 | 旧进程或旧开启结果不能覆盖已关闭的新状态 |
| 导出操作 | 唯一本次身份、来路、固定范围、当前阶段、可否取消、取消清理中 | 采集范围与实时增长的日志；等待与处理完成 |
| 导出结果 | 已核实保存／保存且缺失／失败／未知；实际文件名、大小、位置、缺失原因 | 文件发布成功与UI刷新失败；信息不完整与ZIP写入失败 |
| 清空操作 | 指定本机日志范围、执行中、成功、部分失败及概况刷新 | 删除失败与新日志继续生成；本机日志与公共导出文件 |

异步更新绑定当前操作及页面代际，离开、取消或后续操作后，旧结果不得覆盖新状态；重复点击不创建重复导出或清空。平台调用返回不等于文件已核验，成功条件按实际发布与校验契约确定。

## 4. 初始化、导航与活动训练

- 常规入口：设置数据行→L01→L02→L03→L04/L06，完成返回来路；L05/L08/LD01按各自层级返回。
- 故障入口：业务数据库失败→L07→已有诊断导出→结果→L07；重试正常打开按实际初始化结果处理，不能强制创建空库。
- 无操作日志：可导出当前环境，预览与结果准确说明内容边界；全部必要内容不可采集时失败，不生成空成功。
- 活动训练：允许诊断导出；训练进度、提醒与绝对休息截止继续。诊断任务不调用完整备份的结束训练前置流程，也不与核心事务共享长时间阻塞锁。
- 系统返回：按INT-13取消或等待真实发布结果，状态恢复不重放已完成导出；外部返回恢复原页面上下文。

## 5. UI默认值与技术方案边界

当前界面统一采用：本机常规记录默认开启，最多7×24小时且不超过20 MiB；临时详细模式最长30分钟且重启关闭；用户主动导出ZIP至Download，不自动上传。数字以专项UI规范为统一来源，后续调整同步全部文案。

事件目录、Dart／原生关联、写入前白名单、队列、轮转、异常保护空间、退出信息与诊断包结构已经实现，文档见[事件目录](../../../lib/core/diagnostics/README.md)、[存储控制](../../../lib/core/diagnostics/storage-and-control.md)、[导出格式](../../../lib/core/diagnostics/export-format.md)。性能与设备覆盖按实测范围记录，不能以无法获知的信息制造确定结论。

原始训练数据与保护副本是现有业务数据；本机诊断和ZIP为独立范围，清空不能越界。不得为了诊断增加自动联网、发送文件或向反馈URL附加日志内容。
