# 计划导入导出验收记录

日期：2026-10-03。变更：`add-plan-import-export`。

## 实现与验证

SQLite 是唯一实时数据源；导出在同一读取事务内获取选择的配置后生成 JSON，没有第二份持续维护的 JSON。传输不带本地 ID、训练记录、当前会话或设置。确认导入在一个事务内创建新身份，已有计划和训练状态不变。

最终静态分析 `flutter analyze` 无问题；[全量 Flutter 测试](plan-import-export/flutter-test.log) **74 项通过**（新增 26 项：格式 8、仓库 5、平台 5、界面 8），原有数据库迁移、会话、排序、历史及主题测试均通过。[Debug APK 构建](plan-import-export/flutter-build.log)通过。Android writer 的 2 项 JVM 测试通过；[API 28](plan-import-export/native-api28.log)及[API 36](plan-import-export/native-api36.log)原生集成测试各 3 项通过。迁移故障 fixture 的预期 SQL 错误是回滚测试的一部分，整套测试没有失败。

两台离线、可丢弃的 Android 模拟器完成实际文件导出、卸载、重装、通过系统选择器恢复；逐字段对比计划名、动作顺序、组数、两种休息、空/45.5 kg 重量及空动作计划均一致。测试设备及存储故障证据见[平台存储验收](plan-transfer-android-storage.md)。

跨设备剪贴板流程：在 API 36 应用中实际点击“复制到剪贴板”，显示复制 2 个计划；测试 APK 读取系统原文本，通过主机逐字节转发 657 字节至 API 28 的剪贴板。API 28 清空应用测试数据后，实际点击“粘贴”→“预览计划”→“确认导入”，SQLite 与源配置及文件配置完全相同。转发只通过测试 APK，不增加生产调试入口，也没有在线发送或联网依赖。证据为[原剪贴板文本](plan-import-export/forwarded-clipboard.settrace.json)、[接收后配置](plan-import-export/api28-clipboard-restored.json)。测试类的 clipboardQaRelay 默认跳过，需要显式 `-e clipboardMode capture` 或 `install` 及相应 fixture 才执行。

README 的首页菜单→导出选择→两种输出→文件/文本导入→预览→确认路径已按说明逐步执行。360 dp 和 430 dp、浅/深色、1.3 倍字体的 4 组 Widget 验证通过；按钮至少 48 dp，主要操作可达。模拟器实际 360 dp、1.3 倍字体的[API 36 预览](plan-import-export/api36-preview.png)及[API 28 展开动作](plan-import-export/api28-expanded-preview.png)可读，列表可滚动。导出反馈放在页内，避免 SnackBar 遮挡底部输出按钮。

复查补充：修复合法紧凑 JSON 在保存前重新按导出格式缩进、导致超过 2 MiB 而误拒绝的问题。2 MiB 按原始导入内容校验，保存前再次校验字段。新增真实 SQLite 回归测试：含 14,000 个动作、原始 UTF-8 内容未超限的紧凑 JSON 可以完整保存，动作顺序保留；若按缩进格式重新导出超过上限，导出仍按原规则拒绝。

## 覆盖范围

本次没有连接厂商真机；没有执行网盘、自定义目录、历史/会话完整备份或跨平台文件操作，这些不属于首版计划传输范围。API 24、29 等其他独立系统版本没有单独实测；API 28 和 36 分别覆盖旧存储权限分支及 MediaStore 分支。错误回滚、权限失去和生命周期边界通过明确故障/回调测试验证，不把没有实际发生的磁盘耗尽或厂商行为写为通过。
