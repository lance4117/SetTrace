# 诊断事件目录（schema 1）

52个事件由Dart枚举与原生白名单共同约束，契约测试检查一致性；已接入的生产者与证据见下文及[实施验收](../../../docs/qa/local-diagnostics-acceptance.md)。无操作、能力不可得或记录关闭时不要求每种事件都出现。

每条必含版本、事件、阶段、结果、级别、有限原因码、操作／进程身份、序号、单调时钟域、发生／观察时间和代际。可选父操作、数据集epoch、对象代号、允许的计数／布尔能力及incident引用。所有外部文本、名称、重量、输入、SQL参数、原始来源路径／URI、通知正文和异常消息禁止。

同一操作所有阶段使用同一operation_id；真实事务提交后才记committed，后续失败另记partial_success／followup_failed。缺证据为unknown，日志不驱动业务重放。无可靠数据集epoch时原生对象代号限于当前进程范围，不能跨数据集强关联。

## 字段及边界

- 数值只接受非负安全整数，布尔字段严格为bool；mode只能是DiagnosticValue闭合集合。
- 原始内部对象ID只在受控内存／进程内消息中流转，原生以随机密钥HMAC加类型和数据集epoch后落盘；密钥不导出。
- Dart堆栈只保留settrace／flutter包内位置和dart库位置，原生只保留受认可技术类／方法／行号；不保留绝对路径或异常文本。
- 普通事件最多8 KiB，脱敏堆栈最多32 KiB并独立incident；拒绝、截断、队列丢失不得退回原文。
- 查询／控制和导出是独立类型契约：未知、失败、取消、已保存及部分保存不能合并。目标定位信息仅在私有导出journal，不进入事件或ZIP。
- DiagnosticsClient默认NoOp，记录调用失败不向业务抛出；控制／查询失败保留真实错误。Dart队列128 KiB，另限记录数，并等待在途批次后建立导出边界。

| plan.read／history.read／history.refresh | 常规成功读取保持安静；失败ERROR，详细模式有界DEBUG耗时 | duration_ms和本范围对象；删除后的refresh关联父删除操作，不重复删 |
| plan_transfer | 解析／预览资格、事务导入、复制或核验文件交付；用户选文件取消为cancelled | 允许数量／字节；不含来源正文、文件名或路径；未发布失败不能记提交 |
| backup | protect、core_committed、settings_pending、refresh、recovery；设置后续失败为partial_success | 原持久ledger ID仅内存传递，原生转成独立HMAC correlation_id，跨epoch恢复可关联 |
| rest | synchronize／schedule／claim／output／next／acknowledged／cancelled | revision、round、due_utc／actual_utc、能力布尔与调度mode；无变化同步和每秒倒计时不记 |
| settings／navigation | 实际偏好保存确认、通知目标资格与导航结果 | 仅主题／颜色／语言枚举和能力；不记录任意设置值或通知正文 |
| startup | 原生begin、Dart database／ready、再次打开recovery、系统exit | retry count；历史退出时钟域unknown，不制造单调发生时间 |
| diagnostics.policy | 开启记录或改变详细策略后的确认观察 | enabled，详细模式count=1／0及开启时due_utc；关闭记录后不再追加“关闭成功”日志 |
| diagnostics.clear | 成功清空后的新代际committed | 不含旧内容；关闭记录时不写；所以清空后可能立即有新日志 |
| diagnostics.loss | 原生入队丢失每次drain至多一条WARN | 本批count，直接观察、不通过满队列递归记录；其他损失见持久loss_counts／观察区间 |
| diagnostics.export／unhandled | 后台最终发布结果／有界清理后异常；Dart ERROR、JVM FATAL | export operation身份；当前ZIP不包含封包后的最终发布结果 |

业务事务是唯一提交事实来源。异常堆栈按有限错误类别和清理后帧生成指纹，同指纹60秒窗口聚合；事件中保留incident引用，不能把提交事件合并成计数。发生时间和原生观察时间分别保存；单调耗时只在各自进程时钟域内计算。恢复后的数字对象身份不能沿用旧epoch；epoch未知时限定进程范围。

接口对控制失败如实返回有限原因码，对日志失败非抛错；生产启动显式安装真实client，测试／其他平台默认NoOp。除原生脱敏与重验外，Dart也执行严格枚举、数值和帧清理；拒绝后只计数，不降级存原文。

实现与验证：`test/diagnostics/`、原生DiagnosticsContract／Store／Export／ExitPolicy测试、API36 DiagnosticsPlatformTest及Android实际UI导出。资源和控制详见[存储控制](storage-and-control.md)，包结构见[导出格式](export-format.md)，构建和捕获限制见[故障运维](faults-and-operations.md)。旧API、真实系统迁移、TalkBack与指定低配性能按实施验收保持待验。

## 2026-10-27：事件版本 2

新生产者写 `schema_version=2`，读取器按 1／2 各自白名单验证；旧段和旧事件不重写。
新增 app.lifecycle、rest.callback、rest.transition、rest.audio。trigger 为闭合集合，当前被领取轮次为 round，领取后递增值为 next_round。
notification_requested／sound_requested／vibration_requested 只说明输出请求；audio_state 的 started／completed 是播放器回调，仍不证明用户听见。
策略抑制 INFO，创建／准备／播放故障 ERROR。声音条件只保留有限枚举／整数／布尔，不保存声音名称、URI 或异常消息。
旧事件 sound／vibrate 是旧请求标记，enabled 曾表示是否请求系统通知，旧 output.round 是递增后轮次；不得套用版本 2 语义。
静默作用域连接最近公开祖先；同步入队前捕获来源及祖先，无变化轮询不产生事件。
取消优先使用安排／领取时的 epoch 快照，丢失则 identity_unknown，不用当前数据集强行串联。
restore 过期和训练取消观察只在事务成功后发出，最多 16 个对象及一条截断计数；回滚不产生成功转换。
backup.recovery 核查有 completed／failed／unknown 终态，无任务不是 committed；startup.ready 在备份核查和提醒接线完成后产生。
正常可核实的 user_requested／user_stopped／self_exit 为 INFO，其他退出保留原分类。
构建归属见 process_builds；历史缺失不回填，历史退出对象的构建始终未知。
