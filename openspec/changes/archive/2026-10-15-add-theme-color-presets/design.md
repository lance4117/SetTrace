# Design

## Context

动机与产品范围见 [proposal.md](proposal.md)。本设计是 `focus-a-2026-10-14` 的主题色增量，适用于 C01/C02/C04 设置及共享主题覆盖的全画面，保留 C05/D15/D16 正式品牌呈现。

实际代码基础：
- `AppColors` 已通过 ThemeExtension 提供 `accent`、`accentPressed`、`accentSoft`、`onAccent`、`onAccentSoft`，但只有固定青色的静态浅／深主题。
- `AppTheme` 的 ColorScheme 已映射主色角色；Snackbar 操作色仍静态引用另一明暗模式的青色，需要一并处理。
- `SetTraceApp` 持有 SharedPreferences、明暗及语言状态；`setMode` 在保存成功后才更新 UI。根 Navigator、RootTabs 均使用稳定 key。
- `SettingsPage` 现按外观、语言、提醒、关于排列；`AppCard` 已有 16 dp 内距／圆角。`AppButton`、导航、训练和进度引用共享语义色。
- 已有语义对比度测试、本地化失败注入、长译文与适配矩阵，可在这些基础上补充行为验证。

现有主规范第 3 节只列固定青色色表，INT-10 只定义明暗／语言；本变更新增配色维度和仅针对主题色的即时预览。原有明暗／语言的成功后更新规则不改。实施时将此增量写入当前设计文字规范；历史归档不重写。

## Goals / Non-Goals

**Goals:**
- 用完整的语义强调色组合驱动每个预设，使 Material 控件、共享组件和自定义绘制同步更新。
- 将即时视觉状态与成功持久化状态分开，正确处理连续点击、失败、重试及页面离开。
- 保留应用树身份、草稿和会话，换色不触发业务仓储操作或提醒重新调度。

**Non-Goals:**
- 不新增全局状态框架或依赖；不把配色配置写入训练数据库或计划 JSON。
- 不统一改写明暗、语言和提醒的偏好控制逻辑，不重做现有设置页其余布局。
- 不新增配色预览面板、任意取色器、系统动态配色或品牌资产重着色。

## Decisions

### 1. 独立且稳定的预设 ID

以 `teal`、`blue`、`violet`、`graphite` 为稳定 ID，SharedPreferences 使用独立 `theme_color` 字符串键。不要持久化枚举序号或本地化名称。保留 `theme_mode` 与已有语言键。

在首帧主题构建前解析偏好；缺失、未知 ID、错误类型或读取异常均使用 teal，不因回退立即写入、覆盖其他偏好。旧用户无需迁移；有效颜色与明暗模式分别恢复。

选择四个已配对预设能保证可读性和轻量布局；自由取色会扩大对比度及错误状态范围，不采用。

### 2. 明暗基础语义 + 强调色覆盖

保留现有背景、表面、边界、正文、危险、警告和禁用色。新增预设数据，提供以下五种强调色角色；先取得当前明暗基础语义，再覆盖这些角色生成 AppColors 与 ThemeData。以下色值是此增量的目标值，青色保持当前值。

| ID / 模式 | accent | accentPressed | accentSoft | onAccent | onAccentSoft |
| --- | --- | --- | --- | --- | --- |
| teal / light | #087F6B | #076D5C | #E2F2ED | #FFFFFF | #076D5C |
| teal / dark | #5DD9B6 | #41C6A3 | #203B35 | #102A22 | #5DD9B6 |
| blue / light | #245FC7 | #1E50AA | #EAF0FC | #FFFFFF | #1E50AA |
| blue / dark | #9BBDFF | #82AAEF | #1D3152 | #10264D | #B6CEFF |
| violet / light | #7046B8 | #603AA4 | #F1EBFA | #FFFFFF | #603AA4 |
| violet / dark | #CCB2FF | #B89AEF | #362746 | #2B1648 | #D8C5FF |
| graphite / light | #303A43 | #222B33 | #E8ECEF | #FFFFFF | #303A43 |
| graphite / dark | #D6DDE3 | #B9C4CD | #30383F | #1C252D | #D6DDE3 |

调整 `AppTheme` 为按预设取得浅／深主题，同时可保留默认青色的现有便捷入口，避免无关测试和组件大范围改造。对齐 ColorScheme 的 primary／secondary、container、inversePrimary，以及输入焦点、进度、选择控件、按钮和反馈。Snackbar action 使用在其实际逆表面上可读的对应配色前景，不保留静态青色引用。检查按钮实际 pressed／focus state layer 的合成结果，而不是只验证常量。

配色切换只改变强调角色：正式三线 Logo 和启动器图标继续用现有资产；完成、当前、跳过、待练仍有原文字／符号及真实进度含义。普通文字至少 4.5:1，大字至少 3:1，必要边界、焦点、勾号至少 3:1；卡片装饰线不承担唯一控件识别。

讨论阶段已核算目标主色／文字与浅强调底／文字：按钮文字最低约 4.93:1，浅强调底文字最低约 5.42:1。这不是 Flutter 状态、动画过程、所有页面或 Android 的验收结论；实施时核对全部实际组合。

### 3. 单层主题色卡片

设置顺序为：外观 → 主题色 → 语言 → 适用的休息提醒 → 关于。新卡片不新建路由，不增加确认层或固定操作栏。

| 部分 | 目标 |
| --- | --- |
| 分区 | 与现有分区一致，前一分区间距 24 dp，标题距卡片 12 dp |
| 卡片 | 单层 AppCard，圆角 16 dp、内距 16 dp，使用当前 surface／border |
| 选项 | 青色、蓝色、紫色、石墨，固定顺序，单选 |
| 色块 | 36 dp 实心圆，显示该预设在当前有效明暗模式下的 accent |
| 选中 | 圆内勾号、2 dp 同预设色外圈、3 dp 与色块的间隙；预留外圈空间防止切换抖动 |
| 名称 | 不显示文字标签；本地化颜色名称和默认属性仅用于辅助语义 |
| 目标 | 每项至少 48×48 dp，色块所属整项为可操作区域，相邻项至少 8 dp |
| 提示 | 选项行下间隔 12 dp，14 sp 当前 textSecondary；正常为「点选即刻切换，自动保存」 |

四列等宽，不再测量颜色名称或受字体缩放影响。每项预留至少 52 dp 宽度（含焦点边框）与 8 dp 项间距，容器不足 232 dp 时才两列重排；触控区域至少 48×48 dp。不采用横向滚动。重点覆盖 360／430 dp 与 1.0／1.3／1.6 字号；提示及错误文字继续正常缩放和换行。

选项作为一个有名称的单选组；整项提供唯一名称和 selected 状态。勾号和外圈为装饰，不单独朗读；选中语义不依赖字重和颜色。保留 Material 按压／焦点反馈及既有 Material 图标，不引入图标库。

### 4. 应用级串行保存与最后选择生效

推荐新增小型 `ThemeColorController`（名称为实现建议）与可注入的偏好读写适配，生命周期由 SetTraceApp 管理。SettingsPage 仅呈现状态并派发选择／重试；离开设置不销毁保存流程。

维护：最后成功值 `committed`、当前预览值 `desired`、递增选择版本、单个在途写入、最新待处理目标、失败目标。只串行写颜色键，允许 UI 继续选择；合并尚未开始的中间目标。

1. 选择与当前预览不同的颜色：立即更新 desired、清除旧错误、更新全局主题，不等待动画或磁盘。重复选择当前预览不重复写入。
2. 当前没有颜色写入时开始保存 desired。保存返回 true 才更新 committed；返回 false 或抛异常均为失败。旧请求成功只推进 committed，不将 UI 改回其颜色。
3. 有更新选择时，处理完当前写入再写最新 desired。旧请求失败不回滚更新预览、不显示过期错误；继续最新目标。
4. 最新目标失败且无更新意图：恢复 committed，记录失败目标，显示就地错误和重试。重试重新预览并保存失败目标；用户改选其他颜色则取代失败目标。失败不无限自动重试。
5. 回到已保存颜色也须考虑在途写入：例如青色已保存、蓝色在途、又选青色，若蓝色成功，必须补写青色；不能仅因点击时 committed 为青色而漏写。
6. SharedPreferences 的缓存可能在平台写入前已改变；失败后尝试 reload，但 UI／回滚依据独立 committed，不以失败缓存冒充已保存。reload 失败仍保持可靠的会话内状态和错误反馈，后续读写不得误接受失败缓存。

状态呈现：

| 状态 | 选择／全局效果 | 卡片反馈 |
| --- | --- | --- |
| 已保存 | committed | 正常说明，无成功 Toast |
| 保存中 | desired 立即生效，可继续选择 | 同一提示区显示「正在保存…」；无闪烁进度条，不改变选项布局 |
| 最新保存失败 | 恢复 committed | 「主题色未能保存，请重试。」及至少 48 dp 的「重试」操作 |
| 重试中 | 失败目标立即预览 | 保存中反馈；重复重试合并 |

应用更新帧在输入后及时出现，目标约 100 ms；根 MaterialApp 现有 200 ms 主题动画复用，系统 disableAnimations 时 Duration.zero。动画可被下一选择打断，不阻塞保存；颜色状态过渡过程中不因插值短暂失去必要可读性，必要时将成对前景／背景直接更新。

不为主题色保存拦截 Android 返回、tab 切换或训练通知导航。保存仍由应用层完成，重进设置显示真实当前状态。若进程在写入完成前终止，下次仅恢复实际成功保存的值；不承诺未完成请求已持久化。普通前后台切换不触发重复写入或重新初始化。

只禁用／去重重复目标和重复重试；其他颜色保持可选。色板不存在空列表或远程加载状态；无有效偏好直接使用青色。

### 5. 中英文与辅助表达

通过既有 ARB 及生成流程加入资源，不在组件或控制器存放已翻译错误；错误类型和失败目标保持结构化，展示时读取当前语言。

| 中文 | English |
| --- | --- |
| 主题色 | Theme color |
| 青色／蓝色／紫色／石墨 | Teal / Blue / Purple / Graphite |
| 点选即刻切换，自动保存 | Changes apply instantly and save automatically. |
| 正在保存… | Saving… |
| 主题色未能保存，请重试。 | Could not save the theme color. Please try again. |
| 重试 | Retry（复用现有键） |

默认属性读屏使用本地化完整表达，如「青色，默认配色」，selected 属性交由单选语义表达，避免重复播报。错误及保存状态可被读屏感知，不抢焦点、不逐动画帧播报。语言切换期间重译现有状态，选中的 ID 和失败目标不变。

### 6. 与页面、业务和验证的对应

| 范围 | 重点与验收依据 |
| --- | --- |
| C01/C02/C04、C05 | 卡片顺序、选择／保存／失败／重试，原语言、提醒和关于可达；INT-10、VIS-01–05、ADAPT-01–07 |
| P01–P06、S01–S04、X01–X04 | 全局色更新、输入／选择／滚动保持、原空／错误／禁用状态；INT-01/05/08/10、VIS-01–05、ADAPT-02–04 |
| W01–W06、H01–H05 | 当前／完成／跳过／待练符号、计时与统计不改；INT-03–07/09/10、VIS-01–03、FLOW-03–09/12–15 |
| D01–D16、菜单、许可子页 | Material 与自定义反馈同色、取消／返回／提交保护不改；INT-07/10/11、FLOW-16–19、ADAPT-03/06 |
| A01–A05 | 360／430 dp、长译文与字体、横屏／平板、安全区、读屏和减少动画；ADAPT-01–07 |

计划默认配置与会话快照仍分离，换色不写业务数据库；结束休息不等于跳过剩余组，撤销完成不等于恢复跳过，原候选资格和真实完成分子不改。颜色切换不调用提醒重新同步，不重设绝对截止，不改变自然到期一次反馈或通知目标身份。

在应用级测试中以受控延迟／失败写入验证即时效果、串行合并、补写和重试，而不是仅测试回调。复用对比测试扩展到全部配色及实际交互状态；复用现有适配设施验证卡片和代表性共享界面。Android 实测记录导航、TalkBack、前后台和休息恢复；自动化不能覆盖的设备条件单独标记。

## Risks / Trade-offs

- [颜色写入乱序或错误回滚] → 单写入队列、独立 committed、版本校验、回选补写及可控失败／延迟测试。
- [闪过青色或失败缓存被接受] → 首帧前解析有效偏好、无效值安全回退；缓存与成功状态分离。
- [静态 ThemeData／Snackbar 留下青色] → 按预设生成两套主题，检查所有强调色出口及逆表面，覆盖全局共享界面。
- [极窄容器挤压色块] → 按触控区域要求重排；名称仅提供辅助语义，提示和错误正常增高。
- [颜色插值降低瞬间对比或导致闪烁] → 实测过渡；必要成对角色直接切换，减少动画时关闭过渡。
- [换色重建丢失会话／草稿] → 不按颜色设置应用／路由 key；验证 Navigator、RootTabs、文本控制器及截止保持。

## Migration Plan

1. 后续获准实施时增加主题预设、应用级偏好和卡片，并更新当前设计文字增量；首次无颜色偏好仍为现有青色。
2. 完成 delta 场景、静态检查、现有回归及新主题色行为／适配／Android 验证，记录实际版本与未验证边界。
3. 不需要数据库迁移或备份格式升级。回退旧版本会忽略 `theme_color` 并使用青色，原明暗、语言、训练数据保持。
4. 本阶段仅完成规划，不执行应用实现、主规格同步、归档、Git 提交或发布；这些动作由后续相应请求进入。
