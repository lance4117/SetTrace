## Context

动机和范围见 [proposal.md](proposal.md)。目标基线为 `focus-a-2026-10-14`；必须依次阅读 [设计入口](../../../../docs/design/README.md)、[主规范](../../../../docs/design/SetTrace_UI_Design_System_and_Flutter_Spec.md)、[页面清单](../../../../docs/design/screens-and-states.md)、[交互规范](../../../../docs/design/interaction-spec.md)和[验收标准](../../../../docs/design/acceptance-checklist.md)。HTML／PNG／SVG是对照资料，旧 Figma 概念页和历史设计不是当前规范。

## Goals / Non-Goals

**Goals**

- 用少量共享语义和有明确状态的组件承载完整 A 方案，而不是按 29 张静态图复制页面。
- 保持训练状态所有权、对象身份、异步事务与绝对休息截止，增加稳定且可访问的操作区。
- 将命名、排序替代、错误恢复等呈现改造落实为可测试行为，保留既有功能和平台结果来源。
- 提供按阶段确认、可回退、可逐项追溯到页面／INT／验收编号的实施边界。

**Non-Goals**

- 不重构仓储、会话状态机、数据模型或数据库，不调整备份格式、提醒调度／消费机制、统计口径与权限策略。
- 不引入新路由／状态管理框架、网络字体依赖、WebView 原型运行时或第三方 UI 套件；不为重设计新增权限、平台服务或发布步骤。
- 不将设计稿的示例数值、静态成功提示、浏览器布局或伪系统界面变成正式产品行为。

## Decisions

### 1. 以文字设计契约和现有能力为依据

视觉与交互呈现服从当前 Markdown；业务数据语义服从现有能力规格与经确认的规则。本变更通过 delta 增加呈现、可访问替代和适配契约，保留原有训练、传输、删除与提醒约束。规格与代码的新冲突须停在对应决策处报告，不静默改动业务。

明确处理两处歧义：X01 的选中两个是示例，正式默认仍全选；加减是 Picker 的并行输入方式，保留滑动、吸附和有效档位轻反馈。普通计划名允许重复，导入同名副本是不同流程。设计稿中的系统字体回退、提示时机和日期不构成新默认值。

备选：按 HTML 或旧 Figma 像素复刻。未采用，因为原型无真实事务与系统交互，且会遗漏新功能或误改默认行为。将全部要求放入一个新 UI capability 也未采用；沿用五个已有能力路径更利于发现冲突及同步。

### 2. 演进现有主题和少量组件，显式映射 Material 语义

在 `AppColors` 中保留兼容的已有角色并按需增补 `controlBorder`、`onAccentSoft`、warning 等角色；区分装饰分隔与必要边界。复用 `AppSpace`、`AppRadius` 与当前 Widget 组织方式，保持 Light / Dark 结构一致。

ColorScheme、AppBar、导航、按钮、输入、Dialog、BottomSheet、菜单、Snackbar、进度、单选及开关都映射主规范色值／文字角色，不能遗留独立 seed 配色。特别是 Light accent / accentSoft 只有约 4.26:1，浅底正文必须用 `onAccentSoft=#076D5C`；Dark 与错误／警示分别验证。

共享组件的职责边界：按钮区分主／次／线框／危险及提交／禁用状态；表单字段保留标签、错误与草稿；弹窗／面板提供一致标题、内容滚动和动作区；动作行共享排版但由调用方决定业务资格；数值控件、训练数字／组状态及排序行提供所需可访问语义。只抽取实际重复结构，不建立覆盖全部页面的通用表单引擎。

字体采用离线可用的平台回退和数字特性；目标字形优先 Noto Sans SC／Roboto，但不假定设备必有某字体或新增在线依赖。图标优先现有 Material 矢量资源。布局根据约束、字体和 inset 决定，不复制预览手机外框。

备选：全局改用另一套组件包或仅逐页替换 hex。前者扩大依赖和状态风险，后者容易混色且难以一致验收，均不采用。

### 3. 训练主操作区与滚动正文分离，共用同一会话 State

`WorkoutPage` 保留当前 session、忙碌标记、reload／mutate、生命周期读取和 token 校验入口；将纯展示正文与底部动作区拆开，必要时用文件内或小型 Widget 表达。默认竖屏使用滚动正文加 SafeArea 动作区；正文可滚动到末尾，主按钮不在该滚动区域内。

主按钮从真实状态选择完成本组／结束休息／保存本次训练；尚无完成组时无保存。查看动作、动态跳过、独立恢复跳过、普通撤销、结束以及符合条件的更换入口按现有资格显示，不只放在临时提示条。最多 8 组显示可辨识标记；超过 8 组使用数量摘要和当前待练文本，不制造 100 个狭小目标。

休息仍从现有绝对截止与服务更新，不在分离组件内安排新调度或将弹窗视为暂停。保持 −30／＋30／主动结束与自然到期的区别。横屏／短屏可将任务和主操作并排；平板可分上下文和任务栏，状态和主操作身份不因布局切换而更换。

备选：分别创建训练、休息和完成三个路由，或把所有工具折叠进更多菜单。前者增加状态／返回／提醒身份风险，后者降低新增能力的发现性，不采用。

### 4. 表单保存由调用方提供真实异步结果，UI 只承担提交状态

命名弹窗改为持有输入和错误，接收调用方的创建／改名提交回调；调用方仍使用现有仓储与错误映射。有效输入开始提交后防重复和危险关闭；失败保留名称并显示本地化原因，成功才关闭。保存已成功而列表刷新失败时只重试刷新，不能再次创建同一计划。

保留普通计划名的原规则，不新增唯一性约束。动作配置和本次配置分别使用原参数范围与保存函数。生命周期结束时仍需 mounted／关闭保护；不得为了统一外观把历史删除、跳过等已有确认＋事务流程全改成命名表单的关闭顺序。

危险确认复用视觉骨架，不复用后果文案和业务执行器。删除计划、删除动作、删除记录、放弃训练分别说明影响；D05–D07 根据实际完成数决定动作集合，有记录的放弃仍二次确认。焦点与取消按层级恢复；提交失败不会重置休息。

备选：继续先弹出名称字符串，父页事后 Snackbar 报错。不能满足保留草稿和就地校验，故不采用。

### 5. 排序的两种操作共用候选槽位映射

计划默认排序与会话排序保持不同范围。计划允许调整全部计划动作并沿用原保存；会话仅移动 `movable` 候选，锁定行保持原位置。S02 的上移／下移或等价辅助操作，与拖动使用相同草稿重排规则、候选 ID 及确认提交，不自行实现仓储排序。

S03 解释当前零完成可替换当前、已有完成只调整之后顺序两种情形；候选不足两项保持不可执行。S04 始终定位用户选中的会话动作，只编辑目标组数与两类休息；含跳过先恢复，最小组数来自已完成数。过期草稿拒绝后显示重载，不能自动覆盖新状态或提交旧确认。

备选：只补图标／拖动手柄或实现另一套“直接跳动作”命令。前者没有辅助输入替代，后者改变状态机与含义，不采用。

### 6. 原导航身份、系统边界与异步结果继续由现有所有者管理

根 `MaterialApp`、Navigator key、`IndexedStack`、当前 tab、活动 session ID 与通知去重保留。深层页面不新增一级导航；局部提取 Widget 不重建仓储、提醒服务或根应用。设置选项与语言切换沿用偏好保存成功后更新、失败保持实际值的规则；需要等待提交结果时，仅调整呈现回调与忙碌状态，不重写偏好键或存储机制。

计划传输保持真实文件／剪贴板桥接、默认全选、整份校验、同名副本和确认时冲突；历史保留删除成功与刷新失败的区分、所选月份及过期响应保护。C01–C04 显示真实提醒偏好、权限／渠道、准时能力、调度或偏好失败。Android 文件选择器、权限、设置和通知由系统呈现，不照原型仿造。

备选：为统一新界面重写路由或以统一“所有错误重试”回调处理。会增加重复会话、重复写入与错误语义丢失，不采用。

### 7. 行为测试与视觉／平台证据分层

复用现有 `step_picker_test.dart`、`session_exercise_reordering_test.dart`、`skipped_sets_ui_test.dart`、`plan_transfer_ui_test.dart`、`history_delete_ui_test.dart`、`localization_ui_test.dart` 与关联仓储／平台测试。新增验证只针对可观察风险：固定动作区实际可达、表单失败留草稿且不重复写入、拖动替代保留锁定、加减／滑动同步且不重复触觉、长文本和焦点等；不以样式常量的镜像测试代替验证。

截图覆盖代表性画面与危险状态，并按 29 个画面和 14 类样本清单逐项人工核对；大数据状态与系统错误来自现有夹具和故障注入，不篡改用户库。矩阵基线为 360／430 dp × Light／Dark × 中文／English；字号 1.0／1.3／1.6、长内容、键盘、横屏、768 dp 平板和 TalkBack补充有针对性的组合，不无限重复全量笛卡尔积。

按阶段记录实际命令、设备与结果。已有浏览器资料、旧 Android 截图和 strict 规划校验都不能勾选 Flutter／Android 新界面验收。无法执行的真机条件保持未通过并说明，不能用构建成功代替运行。

## Risks / Trade-offs

- [大范围共享主题变更影响尚未迁移页面] → 先验收共享组件，再逐组改造；每阶段保留相关现有回归，不合并无法独立审查的全屏重写。
- [固定主操作与键盘／大字号竞争高度] → 基于约束保留滚动内容和 SafeArea，主按钮允许增高；横屏重排，不缩小关键正文或遮住末行。
- [提取 Widget 重置计时、服务订阅或通知路由] → 数据所有权不移动，布局只读状态；用绝对截止、稳定根键和现有生命周期／通知回归核对。
- [加减同步 Picker 导致两次 onChanged／触觉] → 两种输入归一到同一有效值通道；控制器同步不再作为第二次用户动作，并核对端点和外部更新。
- [统一弹窗掩盖业务差异、重复创建或重复删除] → 共享样式而非事务，保留对象身份和已有 token；区分写入失败与刷新失败，按真实结果关闭和重试。
- [原型替代了默认全选、真实导入校验或系统授权] → 以 Markdown／主规格约束实施，原型只作参考，专门保留传输和权限回归。
- [保留域层仍发生资格漂移] → 直接读取已有模型条件，补上零完成、动作间休息、含跳过锁定、后续完成再恢复等反例。
- [只验证两张语言／主题截图] → 所有新文案经 ARB，增加长文／字号／切换不重置的行为检查，人工核对 TalkBack 与系统 UI 边界。

## Migration Plan

1. 本轮只提交规划供评审，所有实施任务保持未勾选，不自动执行 apply。
2. 用户后续确认实施范围后，按阶段 1 → 2 → 3 → 4 → 5 → 6 → 7 推进。每阶段开始前核实授权覆盖，结束后展示变更、相应检查与剩余风险；授权未覆盖下一阶段时停止等待。若用户明确授权多个阶段，不重复询问已覆盖范围，但不能超范围实施或发布。
3. 每阶段形成可审查的局部代码改动，保持已有入口可运行；不使用测试数据覆盖个人数据，不为演示执行删除、清库或重建数据库。相关新测试与既有回归在受影响阶段完成，阶段 7 再做集成矩阵及完整回归。
4. 升级验证使用独立测试副本，覆盖安装后原有计划、活动会话（含休息与跳过）、历史、主题／语言偏好和导入格式可继续使用；不得新增数据库迁移或数据转换来完成此 UI 改造。
5. 回退只撤回本变更的界面、文案与组件代码，保留当前支持数据库 v3 和 JSON v1 的应用能力；不回退到不能读取当前数据的旧数据库版本。不自动重置用户偏好或还原历史文件。
6. 新 UI 完成并获用户验收前，不将 docs 中的“待实施”改为“已实施”，不归档此 change、不同步主规格或发布。任何这些收尾动作仍依后续明确授权执行。

## Open Questions
