# Design

## Context

动机与范围见 [proposal.md](proposal.md)。设计来源为 `focus-a-2026-10-14`＋2026-10-16 提醒增量：[主规范 §11](../../../../docs/design/SetTrace_UI_Design_System_and_Flutter_Spec.md#11-休息提醒增强已实现待真机验收)、[INT-12](../../../../docs/design/interaction-spec.md#int-12-休息到期确认与重复提醒已实现待真机验收)、D17–D19、REM-01–06。

当前 `RestAlertRepository`／原生 `RestAlertsStore.claim` 只消费一次事件；`RestAlertService` 只调度 pending，前台 `onDelivered(String)` 交给 Snackbar，后台通知 `setOnlyAlertOnce(true)`。原生读取器严格要求数据库 v3，通道固定声音且禁用振动；通知点击只带会话 ID。这些契约均需配套调整。

主规格现有限定“每次休息至多一声”；本变更改为“每轮至多一次＋待确认时允许下一轮”，由增量规格显式替换。首次 30 秒迟到边界与旧事件不补播保留；已有效首次投递的新版待确认事件允许未来重复。归档前不改主规格或旧变更。

## Goals / Non-Goals

**Goals:** 继续以 SQLite 为提醒状态源，前台与 Android 共用一次领取协议；确认、取消与轮次竞争可验证，界面呈现与训练进度分离。

**Non-Goals:** 不新增组开始记录、改变完成／跳过资格、修改计划／会话快照和历史统计、增加云服务、常驻前台服务、全屏系统通知或绕过勿扰。首次权限说明及准时能力沿用现有流程。

## Decisions

### 1. 在现有提醒表扩展确认与轮次

采用 v4 兼容迁移，仅扩展 `rest_alert_preferences` 和 `rest_alerts`，不重建业务表。新偏好为声音 ID、振动开关、重复开关及枚举间隔；默认三音、振动开、重复开、10 秒。事件保留原 state 枚举：`pending` 为首次未投递，`consumed` 配合新增确认时间、投递轮次、下一轮时间表达待确认，确认后不再参与领取。`consumed_at` 仍表示首次领取时间，原 `due_at` 始终保留休息截止。

领取以事件 ID／revision／预期轮次做条件更新，并验证会话、当前提醒引用及待练目标。首次领取增加轮次并保存待确认状态；后续领取只允许当前预期轮次，下一时间按本次实际处理时刻＋间隔计算。语言或偏好变更增加修订但不清空确认、轮次或原截止；旧投递 token 随之失效。拒绝仅靠 Dart Timer／内存确认，以免后台接收器或进程恢复无法判断是否还需提醒。

停止和训练推进先提交确认／取消，再清理 Alarm、通知及音频。输出前重新复核有效性，确认成功返回前停止排队和正在播放的本次音频／振动；旧 token 在平台取消失败后仍不能再次领取。保留现有“先记录、后输出”的崩溃窗口：不承诺进程恰好在其中退出时绝不漏响。

### 2. 复用前台观察与原生一次性调度

`RestAlertService` 的同步和 `_scheduled` 缓存扩展为事件修订＋轮次＋下一时间，查询同时覆盖首次 pending 与有效待确认事件；自然休息归一化继续保留当前提醒引用。前台计时与原生 Alarm 共用领取协议，切换前后台只改变输出载体，不产生新轮次。

后台接收器短暂工作后只安排下一次单次 Alarm，不启动 Flutter 引擎，不在回调内循环等待。沿用精确／非精确能力降级；Doze、厂商限制和 Android 通知冷却可能使 10 秒显著延迟，界面明确这一点。拒绝为追求精确频率新增常驻服务；迟到时最多处理一个有效轮次，不补发累计次数。首次迟到超过原截止 30 秒仍过期，该门槛不套在重复轮次上。

关闭重复立即清除下一轮，确认入口保留；开启重复或保存新间隔成功后从当前时刻安排下一轮，不立即响。新声音／振动配置作用于之后输出，不打断当前段落或补播。后台通知权限不可用时保留待确认状态，停止无效后台重复唤醒；回前台重新核对后只安排未来轮次。

### 3. 单个呈现协调器与带身份的确认

在 `rest_alert_platform.dart` 和桥接契约中将投递／点击载荷由正文或会话 ID 扩展为会话、提醒 ID、修订和轮次；文案从最新有效状态读取。`app.dart` 复用现有启动呈现队列，依次处理欢迎、待处理通知导航、权限解释及 D17；所有编辑／确认／面板的关闭被协调器感知，声音不因等待 UI 而暂停。

同一进程、同一事件至多挂一个 D17；返回收起标记与持久确认分离，后续轮次及普通前台返回不强制重开。W01 保留“停止本次提醒”，弹窗与页内入口共用幂等确认。完成本组、跳过、撤销和结束保持原仓储事务含义，只在相应原事务内失效提醒；“结束休息”不变成“跳过剩余组”，确认不写组记录。

通知导航需能区分“训练页已成功呈现”与“该页面最终退出”，避免等待现有 `openWorkout` 返回的整个页面生命周期才确认。成功呈现最新所属会话后确认对应事件；旧通知不能取消该会话的新休息。失败保留可重试状态。D17 确认后保留原页面；训练页继续显示原固定“完成本组”，关闭手势防穿透。

| 画面 | 实施落点与状态 |
| --- | --- |
| D17 / W01、W03、W04 | `app.dart` 协调、训练页停止入口、共享弹窗组件；待确认／提交／失败、返回收起、无横幅 |
| C01/C02/C04 | `settings_page.dart` 复用单层 AppCard；总开关→声音／试听→振动→重复→间隔，保存失败及权限说明保留 |
| D18/D19 | 共享单选面板，选择草稿与试听分离；保存成功关闭，返回／下滑取消，失败留面板；试听新段替换上一段，离开停止 |
| C03、D15/D11 | 带事件身份的通知导航与串行呈现；失效不误开其他会话，队列展示前复核 |

尺寸和语义色直接遵守主规范 §11。新增文案进入现有 ARB，动作名保持用户原文；浅深×四主题色、长文本、1.6 字号、短屏安全区和 TalkBack 均覆盖，减少动态效果时关闭非必要位移；重复不重复播报焦点。

### 4. 打包音频与受系统约束的输出

默认三音约 1.5–2 秒，另打包双段电子提示与短音＋“休息结束”／“Rest is over”中英文语音；不播报用户动作名，不调用网络语音。语音按现有应用语言解析，未来无对应音频的语言回退英文，不增加第二套正式语言注册表。前台和后台复用同组声音，振动为两次短振动并补充 Android VIBRATE 权限。

Android 8+ 通道声音与振动创建后受系统管理，不能只更新现有通道参数。按声音／语音资源和振动配置懒创建版本化通道，迁移时保留原通道静默／禁用选择，能力检测和设置入口指向当前有效通道，不以新通道绕过用户限制。前台按同一通道／铃声／勿扰策略单独输出，后台由本轮通知输出，不同时另播一份；同 ID 通知允许新领取轮次提示，普通内容刷新保持静默，不沿用会屏蔽所有后续轮次的 `setOnlyAlertOnce(true)`。

### 5. 恢复和设置的明确边界

v3 已 consumed 的事件迁移为已确认，cancelled／expired 保持终态；只保留未来 pending 的首次资格。v4 已有效投递且未确认的事件恢复时复核目标，可恢复视觉及下一未来轮次，不立刻补响；已确认、已取消及未首次投递的过期事件不复活。确认和新偏好由数据库保存，缓存失败不冒充成功。

## Risks / Trade-offs

- [后台间隔被系统拉长或通知被冷却] → 明示目标间隔、测量实际投递，不用调度返回成功冒充送达；无权限不持续空唤醒。
- [通道更新后音色未变或绕过静默] → 版本化通道及旧用户限制迁移，验证既有静默／关闭通道和音色切换。
- [确认、旧通知与新休息竞争] → 全程绑定事件修订，事务领取与失效，输出前复核，导航成功后确认。
- [重复提醒带来耗电和打扰] → 可关闭、可选较长间隔，单条通知与短段音频，确认或推进后立即清理。
- [生成图与真实控件细节不同] → 文字规范优先，计划／记录图标及其他既有界面不按示意图替换；记录 Flutter 与真机实测边界。

## Migration Plan

1. Flutter 负责 v1/v2/v3→v4 的顺序迁移、默认偏好与旧终态转换；保存已有提醒总开关、计划、历史、快照、组记录和原截止。原生只读版本并拒绝未支持版本，不执行迁移。
2. 同步原生 v4 契约，升级启动后清理旧系统投影、仅重新安排未来有效首次或下一重复；旧 Intent 无轮次时不得当作新版重复使用。
3. 通过迁移／并发／UI 回归和 Android 前后台、锁屏、声音振动验收后再更新运行说明及设计实施状态；真机未测项保留待验，不将生成图或模拟器标为真机通过。
4. 回退采用兼容 v4 的修复版或关闭重复偏好；不安装只能读取 v3 的旧包、不删库降版，不回滚用户训练记录。
