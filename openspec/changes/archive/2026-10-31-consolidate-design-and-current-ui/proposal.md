# Proposal

## Why

设计资料分散在 `docs/design/` 的多批次交付与 `work/ui-sketches/`，当前入口仍混用旧应用基线、旧画面和过期实施状态，例如诊断功能已有实现但首页仍标为待实现。需要将有效资料集中为一套与最新应用构建对应、可浏览并可追溯的 UI 参考，旧稿及杂乱工作文件统一归档。

## What Changes

- 保留 `docs/design/README.md` 为唯一设计入口，建立 `docs/design/current-ui/` 与 `docs/design/archive/` 两个主要阅读分区。
- 将现行视觉、组件、页面与交互规范整合到 `current-ui/specs/`，保留 `focus-a-2026-10-14` 及后续已实施增量的来源、稳定页面 ID 和验收编号，修正过期的实施描述。
- 将旧原型、被替代的截图、未选用品牌方案、临时产物及工作稿按日期／主题归档；记录原路径、归档原因、文件哈希和替代资料。相同内容仅保留明确主版本，并记录全部来源，不丢弃独有文件。
- 以实施时确认的最新源码提交构建应用，在隔离的 D 盘 Android 模拟器中采集当前 UI，形成页面／状态目录、实际截图、完整滚动参考、离线可浏览图册和构建／截图清单。旧图片不得改名冒充当前构建截图。
- 覆盖 P/W/S/X/H/C/D/A 页面，以及 B/E 备份、L/LD/LE 诊断、许可和系统声音等增量；依据 INT-01–13、VIS/FLOW/ADAPT、COLOR、REM、HIST、BK、LOGUI 记录正常、空、禁用、提交、失败及返回状态。
- 验证记录关联实现、用例、环境与证据，区分本次通过、历史证据、已实现待验、未实现／发现差异；完整状态索引与实际已取得截图的覆盖率分别表达。
- 同步项目 README、OpenSpec 当前阅读指引及受迁移影响的工具路径；保留历史验收与已归档 OpenSpec 产物，处理旧引用兼容，避免多个目录继续充当当前主版本。

## Capabilities

### New Capabilities

无。本次建立开发设计资料及其维护规则，不新增应用功能或产品行为能力。

### Modified Capabilities

无。现有七项主规格的业务含义保持；本变更在 `.openspec.yaml` 设置 `skip_specs: true`，按文档／工具整理处理，不创建规格增量或修改主规格。

## Impact

- 主要产物：`docs/design/**`；整理来源包含 `work/ui-sketches/**`。旧 QA 报告及证据保留在 `docs/qa/**` 并由新资料引用，不改写其结果与原始证据。
- 接入调整：项目 `README.md`、`openspec/config.yaml` 的当前资料路径／事实，以及 `tool/generate_android_icons.py` 等确有迁移依赖的工具路径。可补充仅供资料采集、图册生成及校验的工具，不扩大为应用开发。
- 保持应用界面与业务实现、运行品牌资产、数据库、计划／备份／诊断格式、提醒规则及依赖不变；不重新设计产品、不自动修复发现的 UI 问题、不改写历史规格／变更、不执行发布或提交。
- 当前规划参考为代码 `306b9bc`、应用版本 `0.3.1+12`。探索所见最新 APK 与旧验收包哈希不同，且本轮截图仅在内存中查看；实施必须重新固定源码与构建身份并保存证据，不能把探索结论直接登记为本次交付通过。
- 构建、日志、截图和工具工作文件使用项目所在 D 盘；SDK、AVD、共享缓存及 TEMP/TMP 遵循既有 D 盘约定，复用现有环境，不自动安装工具或新建设备。
- 本次调用仅完成规划；资料迁移、重新构建、截图采集和验证在用户后续明确启动 apply 后实施。
