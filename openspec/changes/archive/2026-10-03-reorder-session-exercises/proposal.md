# Proposal

## Why

健身房器械被占用时，用户需要在完成 A 后先练 C，再回来练原定的 B。当前 App 只允许修改计划顺序，本次训练开始后只能按固定顺序推进，因此需要允许在训练中调整待练动作，同时保留已有进度与休息。

## What Changes

- 在训练页和动作间休息页提供“更换下一动作”，选择待练动作后将它移到下一待练位置，其余待练动作保持相对顺序。
- 在“全部动作与编辑”中增加剩余动作排序，拖动后确认保存；取消不改变训练。
- 以本次记录判定排序范围：没有任何完成组的动作可移动，包括已经显示为当前动作但尚未记录第一组的 B；已完成动作及已记录部分组的当前动作不可移动。部分完成动作继续做完，允许预先调整其后续待练顺序。
- 排序仅修改本次会话，保持动作配置、完成组、完成时间及正在进行的休息；当前休息不因换动作而重新计时或跳过。
- 让当前动作由稳定会话动作标识定位，排序、组推进、撤销及重启恢复保持一致；拒绝过期或无效排序，不覆盖最新训练状态。
- 历史详情按本次会话保存的动作顺序展示，原计划、下一次新训练和既有历史保持原样。

本次不支持已部分完成动作与其他动作交替练习，不增加“开始本组”按钮、动作计时、导入导出或超级组，不改变通用倒计时方案。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workout-session`：增加本次待练动作排序；明确训练快照可由本次操作调整、休息按已完成动作保持、撤销按完成记录定位，以及排序后的组推进和重启恢复行为。
- `workout-history`：明确记录详情使用本次最终保存的动作顺序，与原计划默认顺序独立。

## Impact

- `lib/features/workout/workout_models.dart`、`workout_repository.dart`、`workout_page.dart`：稳定动作定位、原子排序、进度与编辑权限判断、选择及排序界面。
- `lib/core/database/app_database.dart`：SQLite v1 升级到 v2，增加当前会话动作 ID 和内部组完成序号，保证排序后定位及撤销顺序；迁移已有会话而不删除数据，同步数据库说明。
- `lib/features/history/history_page.dart`：沿用按会话排序加载的详情，验证本次顺序正确；不新增执行时间线。
- 数据库迁移、仓库、Widget 与历史回归测试；新增 Android 排序验收文档并更新 README 使用说明。
- 复用现有 Flutter、SQLite 和组件，不引入新依赖、权限、账号或服务，不修改计划排序功能。
