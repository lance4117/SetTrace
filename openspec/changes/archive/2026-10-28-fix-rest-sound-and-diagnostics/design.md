# Design

## Context

动机、证据边界及本次范围见 [proposal.md](proposal.md)。本设计适用于现有 Flutter／Kotlin 项目，不是后台服务方案。

已核对的实现约束：

| 位置 | 当前情况 | 设计影响 |
| --- | --- | --- |
| `RestAlertsBridge.kt` | 通过字符串 `android.resource` URI 引用音频；播放器创建为空直接返回、异步错误被消费；调用后仍可能置 `sound=true` | 消除打包资源依赖，并把请求与观察结果分开 |
| `RestReminderControls` | D19 三音选择及各项试听，D18 间隔选择 | 只替换声音区域，不重做整页或删除其他设置 |
| `rest_alert_preferences`／`BackupSettings` | SQLite CHECK 与完整备份均限定 `three_tone/double_beep/voice` | 保留旧值及备份格式，不把 `system` 写进数据库 |
| 原生通知通道 | 按声音、语言、振动产生多个通道；已创建通道的听觉行为由系统控制 | 需要有限迁移，不能只修改已有通道的默认声音 |
| `diagnosticObserve` | 静默读作用域仍分配父操作身份，子事件可能指向未写出的父操作 | 修复可见祖先与异步上下文，不开启逐秒轮询日志 |
| 取消入口 | 只传提醒数字 ID，epoch／revision／round／操作上下文丢失 | 使用已有业务判断得到的事实传递诊断上下文 |
| `reconcileStartup` | 写入 started，同时 `recordSuccess=false` 抑制成功终态 | 核查结果需要独立终态，不能把无恢复任务记为提交 |
| 诊断契约及校验工具 | 只识别事件 1／ZIP 1；摘要滚动保留最后 64 条匹配记录 | 显式版本升级、双版本验证和按操作选择摘要 |

设计依据为 `focus-a-2026-10-14`、`diagnostics-ui-2026-10-23`；已读取主 UI 规范、页面清单、INT-10/12/13、验收清单和 `app-experience`／`app-diagnostics` 主规格。现行 D19 的自定义声音要求与用户本次明确选择系统音存在差异，由本 change 的 `app-experience` 增量替代；其他页面／交互不随之改义。

## Goals / Non-Goals

**Goals:**

- 使用不依赖 APK 自定义音频资源的系统声音，在前后台遵守同一声音策略和用户限制。
- 在不改变提醒资格和事务结果的前提下，提供可关联、可区分证据等级的声音及提醒日志。
- 保留升级前数据、通知限制、旧诊断证据与开发侧独立校验能力。

**Non-Goals:**

- 不引入前台服务、唤醒锁、自启动、HyperOS 引导、锁屏定时自测或新的调度 API；不修改 `expireElapsed`、首次 30 秒有效窗口、重复不补发、领取竞争和通知导航规则。
- 不重写历史日志，不推断 20:20 后台漏提醒的确定根因，不将“本次声音正常”升级为“后台必达”。
- 不更改 SQLite v6、完整备份 1、训练写入／恢复、两类撤销、默认计划与本次快照、真实完成比例和日志控制策略。

## Decisions

### 1. 运行时声音与历史偏好分离

生产声音模式固定为 `system_notification`。保留 `RestAlertOptions.sound` 和数据库／完整备份的旧枚举，作为旧版可读的历史兼容值；新装仍沿用合法存储默认值，升级不为声音另写业务表，修改振动／重复／间隔时不重置历史 sound 值。完整恢复导入任一旧值后仍播放系统音；导出继续输出合法旧值，并在格式说明中说明它不再表达新版的实际声音来源。

系统通道与系统设备声音不属于可迁移业务设置，不新增到完整备份。API26+以当前休息通道的有效声音为准，新装默认使用符号型系统通知音 URI，使系统默认音变化可在后续播放时生效；用户在系统中单独选择的该通道声音和静音选择优先。旧 API 使用系统默认通知音及既有通知构建规则。

选择理由：写入 `sound_id=system` 会触发现有 CHECK／备份校验失败，扩大数据库及回退范围；继续播放 APK raw 资源则保留本次资源缺失风险。

### 2. 有界通知通道迁移，继承限制而非恢复默认权限

建立独立于声音名称和语言的系统音通道族，最多两个稳定通道，分别用于应用振动偏好开／关。保留这两个变体是为了在 Android 通道听觉配置不可随意改写的约束下，维持现有独立振动开关；不再每个音色、语言或重试生成新通道。

迁移由原生后台串行处理，在未来有效输出／主动试听前确认完成：

1. 读取当前实际旧通道和可读取用户设置。旧通道身份失效时，仅扫描本应用已知旧通道族，采用可证实的限制；无法确定用户选择时保守受限，提供系统设置入口，不猜测可发声。
2. 新装且不存在旧通道时使用系统默认通知音；应用自带旧 URI 改为系统默认。用户已设的静音、禁止通知、较低重要性、关闭振动和可读取的自选系统声音继续优先；API26–29 无法可靠判断用户是否修改的情况采用保守继承。
3. 创建或检查目标通道，确认实际状态后再记录迁移版本／目标族标记；部分失败不标成功，不通过反复创建通道重试“解除限制”。标记存在但通道缺失仍重新检查，覆盖系统迁移或外部变更。
4. 后续切换振动变体时，保持逻辑提醒的已知静音／封禁／低重要性／用户禁振限制；已有目标通道更严格时不提升。不能以切换变体绕过系统用户设置。读取状态以当前平台为准，不以缓存宣称允许。

若平台不允许把已经存在的目标通道调整到应继承的更严格限制，应用采用静默发布或停止受限输出，并说明需要系统设置；不尝试再创建第三个通道。单独关闭应用振动不得使原已静音的声音恢复。用户在系统中明确解除限制后重新读取实际状态，不能用永久缓存阻止其后续选择。

迁移标记只存原生应用设置中的有限版本与自有通道身份，不存用户声音 URI，不纳入完整备份或诊断 ZIP。迁移不发送测试通知、不补响、不修改提醒 revision／due；系统通道迁移失败只影响未来声音输出，并通过既有提醒失败反馈和有限日志说明。

旧通道不批量删除，不要求卸载／清数据。方案没有选择简单删除重建原通道：它既不能可靠改变旧设置，也可能破坏用户限制。

### 3. 单次声音播放和策略检查共享，后台声音交给系统

原生抽出可注入的声音策略与单次播放器适配，生产读取当前通道、铃声模式、通知音量、勿扰及能力；缺失读数标未知。前台实际提醒和主动试听复用该策略与同一声音来源。前台仍通过原生播放器播放系统声音，保留可观察的创建／准备／开始／完成／错误回调；后台调用系统通知接口，不再由应用并行补播音频。

播放器创建为空、URI 无法打开、准备失败、异步错误均返回有限分类并清理资源；不保存异常消息、URI 或声音标题。异步回调捕获本次播放身份和提醒 revision／round，不沿用“当前正在播放”的可变身份。取消、下一次有效输出、离开试听页面及运行时结束清理旧实例；迟到回调不释放新实例、不触发新一轮。单次播放最长 10 秒，长音达到上限记录有界停止，预览不循环；该资源边界不改变提醒轮次调度。

策略抑制是正常 INFO 事实，例如静音、音量为零、勿扰或通道无声；实际创建／播放故障为 ERROR。播放故障不抛回组完成事务，不自动重复 claim；振动和视觉反馈沿既有独立策略尽力执行。

选择保留可观察的原生播放器适配，而非仅把 `play()` 返回当成功：需要捕获本次“有振动无声音”的技术失败。平台没有最终播放反馈的路径只记录 requested／unknown，任何路径都不记录“用户已听见”。

### 4. 声音设置的局部交互

本 change 的局部设计增量命名为 `rest-system-sound-2026-10-27`，仅定义在本设计中，不代表已修改当前设计入口或已实施。

| 页面／交互 | 目标表现 | 状态与边界 |
| --- | --- | --- |
| C01/C02/C04 提醒卡片／INT-10/12 | 原声音行改为“提示音／使用系统通知音”；若通道已自选或无声，显示“在系统中设置”或“系统已设为静音”等有限真实状态；保留独立“试听”和“系统通知设置”操作 | 读取中、不可用、受限、播放失败分别表达；不显示原始 URI、声音标题或诊断技术码 |
| 声音试听／替代 D19 | 播放当前有效声音的一段；重复点击不叠音；已存在真实提醒输出时拒绝预览，不中断提醒 | 不发系统通知、不振动、不领取轮次、不改偏好或训练；静音显示原因，失败有重试／系统设置入口 |
| 系统通道设置 | 优先打开当前休息通道；平台不支持时退回本应用通知设置；均无法打开时就地反馈 | 返回重新读取真实能力，保留设置滚动和焦点；不因返回立即补响，不自动申请权限 |
| D18 | 继续 10／15／30／60 秒草稿保存与取消 | 保存中防重复，失败保留草稿，返回／下滑不保存 |
| D17、W01/W03/W04、C03 | 弹窗、停止入口、后台同条通知和有效返回不变 | 声音变更不重开弹窗、不完成组、不暂停截止、不修改提醒资格 |
| L01–L08／INT-13 | 日志技术详情只在包中；原导出及清空体验不变 | 新格式不能使读取失败冒充空日志，也不破坏 L07 独立故障导出 |

沿用 AppCard、现行 Material 控件、CMP-01/02/05 和语义主题；使用正式中英文 ARB（如“使用系统通知音／Uses system notification sound”“试听／Preview sound”）。独立操作至少 48×48 dp，1.6 字号时声音说明与操作换行或重排，不靠缩字。试听时可取消，离页立即停止，错误 live region 只在状态变化时播报；应用返回与系统设置返回保持原页面。覆盖四主题色浅深、360／430 dp、短屏横屏、768 dp、长英文及 TalkBack／减少动态效果。对应 REM-01–06、VIS-01–05、ADAPT-01–07、LOGUI-01/11/12。

### 5. 诊断上下文在既有执行边界传递

使用独立的不可变诊断上下文，包含操作／可见祖先、generation、epoch、提醒对象、revision、当前轮次与触发来源。仅通过内存、现有原生调用和受控闹钟 extras 传递，不把诊断身份写入业务表；业务领取与取消始终以既有业务条件为准。

- 静默只读作用域不作为公开父节点。子事件优先连接最近有记录的祖先；没有祖先时 parent 为空，不能生成幽灵引用。排队的同步请求在入队时保存来源与祖先，不能在 `_tail` 真正执行时误借另一操作的 Zone。
- 组完成等业务操作触发的提醒同步保留其祖先；原生 schedule／claim／output 继续保留同一可关联操作身份。
- 显式确认、主动结束等取消传递已有的 epoch 和提醒事实。`cancelExcept` 等平台清理仅在原生后台、利用当前已打开的业务只读上下文补齐信息；不为日志在主线程开库、不改变取消结果。若对象已不存在且无法证实 epoch，保留 unknown 作用域并标记 identity_unknown，绝不猜用当前 epoch 强行关联旧对象。
- 日志被关闭、清空、丢弃或跨出保留期后，父节点／对象缺失仍可能发生；清单和分析只说明证据边界，不能宣称每个引用永远可解析。

### 6. 补充关键事实，不记录无变化的轮询

增加有限事件族 `app.lifecycle`、`rest.callback`、`rest.transition`、`rest.audio`；复用 `rest.synchronize`、`rest.cancel` 和启动事件补充终态。新增字段和枚举同时进入 Dart、原生持久化与导出白名单。

| 信息 | 版本 2 语义 |
| --- | --- |
| `trigger` | startup、resume、foreground_poll、alarm、delivered_callback、training_change、acknowledge、settings_change、platform_cleanup、preview、unknown 等闭合集合 |
| `round`／`next_round` | 同一次 claim 和 output 的 round 都为被领取轮次；递增后的轮次单列 next_round，安排下一轮明确其目标 |
| `notification_requested`、`sound_requested`、`vibration_requested` | 本次向平台提出的输出请求，不复用 `enabled`；enabled 只保留真实偏好含义 |
| `audio_state` | requested、started、completed、stopped、failed、suppressed、unknown；状态有实际平台证据才产生 |
| 声音条件 | ringer_mode、notification_volume、interruption_filter、channel_has_sound、channel_importance、读取可用性；均是有限数值／枚举／布尔，不包含声音 URI 或标题 |
| 状态转换 | 实际 before_state／after_state、reason、count 或有界对象事实；发生时间与 observed_time 仍分离 |

生命周期只记录真实变化；闹钟回调在收到后记录一次。同步触发来源写入后续有意义的事件，无变化的一秒同步不写事件。Dart `restore(expireElapsed: true)` 等现有过期路径记录实际改变的行数和有界身份：在原有事务内获得变更事实，成功提交后发出 transition；未改变状态不写，事务失败不伪报过期成功。大量变更采用有界逐对象事件加总数／截断标记，不把全表复制进日志。

`backup.recovery` 的核查 started 必须配 completed、partial_success 或 unknown/failed 的实测结果；正常无任务不写 committed。`startup.ready` 的版本 2 语义仅表示完整初始化含备份核查和提醒接线已就绪；此前数据库可读使用已有 database 事件，不以构造 Flutter widget 冒充全初始化成功。改变的只是观察时间点，不把日志成功作为应用启动条件。

`user_requested`／`user_stopped`／`self_exit` 的可核实正常退出采用 INFO；崩溃、ANR、资源退出及未知分别按既有证据分类，不能单凭缺少终态升级成崩溃。

### 7. 显式版本 2 和构建归属

新事件 `schema_version=2`，新 ZIP `format_version=2`。日志分段头识别版本 1／2；不往版本 1 活跃段混写版本 2，不原地升级旧段。Dart 与原生新生产者同时切换，新导出器按各版本白名单重验旧数据，并保留事件原版本。版本 1 的 `sound`、`enabled`、round 等按旧语义呈现，不补造旧播放结果、当前轮次或父操作。

进程启动时保存有限的真实安装 version／build／可用的开发构建标识和进程关联；Dart 通过桥接获得同次安装身份。新事件通过本地 token 关联该元数据，ZIP 2 的清单提供进程与构建映射，并标明未知／缺失。不能将导出时应用版本回填到升级前进程；历史 `startup.exit` 的观察进程不等同被退出进程，不能为它冒配构建。元数据受既有容量和清空代际管理，不存设备持久 ID、源目录或密钥，也不在手机上反复计算整个 APK 哈希。

未知事件版本继续拒绝、计数并显示局部缺失。纯旧包的独立校验仍支持 ZIP 1；ZIP 2 可含版本 1／2 事件。旧应用回退后按既有未知版本边界处理版本 2，不保证读取新日志，不重置用户诊断控制。诊断控制／导出 journal 的状态协议不随格式版本改义；进行中的旧 journal 仍按原目标及 digest 核查，不重放导出。

选择显式升级而非给旧字段偷偷换义：本次改动直接影响离线分析结果，严格验证器应能明确区分新旧含义。SQLite 和完整备份版本不参与此升级。

### 8. 有界、按操作的摘要

最多 64 条操作摘要、最多 32 KiB UTF-8。流式扫描后使用两个有界候选池：故障／未知／已知证据缺口优先池和普通关键操作池。普通操作按 operation_id 归并 started／committed／completed，不把同一提交打印两遍；出现 partial_success 时保留“核心已提交、后续失败”的完整含义。

先选择异常候选，再用普通操作补足；异常超限时按确定性的严重程度及最近观察次序选取，并报告被省略的异常数量，不声称全部展示。选中后按可解释时间排序，同域以序号／单调顺序处理墙钟异常；展示本地可读时间与偏移，同时保留 UTC 毫秒。汇总包含事件数、归并操作数、摘要省略数、已观察丢失、缺口和旧版本解释限制。缺少终态只能列未知，不能归因为 HyperOS 杀进程。

两个池和归并缓存都设置固定条目／字节上限，淘汰可见；所有原始合法事件仍在 ZIP 中。既有事件 8 KiB、堆栈 32 KiB、总队列 1 MiB、日志 7 天／20 MiB、辅助 1 MiB、staging 24 MiB 不扩大。

## Risks / Trade-offs

- [新通道意外解除用户限制] → 明确迁移与振动变体继承规则、跨版本实测；不确定时受限，不删除重建来恢复声音。
- [旧声音字段与新运行时不一致] → UI／备份格式说明明确历史兼容含义；保留旧值往返，不增加新枚举或伪称可恢复手机声音设置。
- [诊断钩子改变业务时序] → 提交后观察、不可变上下文、无变化不写；故障注入验证日志不可写、关闭和清空时训练及提醒结果不变。
- [旧日志被新语义误读] → 事件／ZIP 显式升级、版本专属验证器、混合样本和旧工具兼容测试；历史证据原样保留。
- [系统音无法提供最终可感知证据] → 前台仅记录播放器实测状态，后台仅记录通知请求；真机听感独立确认。
- [资源测试只在 debug 成功] → release 安装与实际试听为声音验收必要项；本机 APK 线索不能替代手机安装身份核对。
- [诊断扩充造成噪声或预算超限] → 转换才记录、闭合词汇、固定候选池、异常聚合和截断计数，保留原资源上限。

## Migration Plan

1. 实施时先更新当前声音文字规范及事件／导出文档，明确 D19 替代范围；不重写历史归档。
2. 先实现并验证双版本读取和导出，再启用版本 2 生产者；已有版本 1 分段受原保留规则管理，不清空用户日志。
3. 接入系统音适配与最多两个目标通道；确认目标实际状态后记录迁移标记，失败可重试但不自动发声。首次进入设置仅展示实际状态，主动试听才播放。
4. 保持 SQLite／完整备份兼容；用三种历史声音值分别测试新装、升级、恢复、导出和回退读取。声音变更不延长或重启当前休息。
5. 在 D 盘构建 release，保存 APK 哈希、源版本及对应符号，真机安装后核对版本／构建并实际试听与到期提醒。测试中产生的后台未达仍记录为未解决，不冒称本 change 已完成后台可靠性改造。
6. 回退应用不删业务数据或公共 ZIP；旧版对版本 2 日志的未知版本限制如实说明，系统通道可能留存。不得为回退清空诊断或重置系统静音。
