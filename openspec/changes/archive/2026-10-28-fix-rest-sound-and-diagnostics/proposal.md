# Proposal

## Why

用户在小米 HyperOS 真机使用 SetTrace `0.3.0+11` 时反馈提醒只有振动、没有声音，并更正 2026-10-27 约 20:20 的漏提醒发生在后台。诊断包能证明已安排提醒，却不能解释声音失败和后续取消；本机同版本 release APK 中缺少自定义音频资源是声音故障的重要线索，但尚未核实手机 APK 与本机构建的哈希一致，不能将其写成已确认根因。

## What Changes

- **BREAKING（声音交互）**：以系统通知音替代三音、双段电子提示和短音语音，移除 D19 自定义声音选择；C01/C02/C04 提供实际声音状态、独立试听和本应用休息提醒通道的系统设置入口。保留总开关、振动、重复、D18 间隔，以及前台 D17 不发系统横幅的规则。
- 新装采用系统默认通知音；升级采用有界、可重试的通道迁移，保留用户已关闭、静音、降低重要性及禁用振动等限制，不以新通道绕过限制。旧数据库与完整备份中的三个声音值继续兼容，仅作为历史配置保存，不再决定播放资源。
- 声音输出区分策略抑制、已请求、平台可观察的播放状态及失败；试听失败提供可理解反馈，后台通知只证明提交请求，不宣称用户已听到。系统静音或资源不可用不触发补领轮次、不重放训练事务。
- 修复诊断链路中的取消对象作用域丢失、不可解析的父操作引用、启动核查只有开始没有结果、当前轮次与下一轮次混用，以及 `enabled=false` 被误读为提醒关闭等问题。
- 对现有生命周期变化、闹钟回调、同步触发、实际取消和过期转换增加有界观察，不改变当前调度、恢复、领取、过期和重复规则；记录可读取的声音限制及有限错误类别，不记录声音 URI、名称或异常原文。
- **BREAKING（诊断解析器）**：新事件使用显式版本 2、新导出使用诊断包格式版本 2；新读取器兼容保留期内版本 1 和版本 2，不把旧字段重新解释成新语义。摘要按操作归纳，优先保留故障与证据缺口，并提供实际省略数量和进程级构建身份边界。
- 增加 release 声音、旧通道迁移、混合版本日志、隐私和实际真机试听的验收任务；未执行的物理设备听感和后台场景保持待验。

本次不包含训练前台服务、保活／唤醒锁、HyperOS 无限后台／自启动引导、锁屏定时自测、权限体系扩展，以及后台漏提醒的调度／过期策略修复。不将后台事件重新标为前台故障，也不承诺本次即可解决后台漏提醒。

## Capabilities

### New Capabilities

无；复用既有能力。

### Modified Capabilities

- `app-experience`：更新「休息提醒设置与权限反馈」，定义系统音、试听、系统设置入口、旧通道迁移及旧声音配置的兼容行为。
- `app-diagnostics`：补强结构化关联、关键业务终态、提醒因果观察、声音结果、版本兼容和人读摘要要求。

## Impact

- Flutter：`lib/features/rest_alerts/rest_reminder_controls.dart`、`rest_alert_platform.dart`、`rest_alert_service.dart`、设置页及正式中英文 ARB；`lib/core/diagnostics/` 的生产、作用域和双版本契约；启动／备份核查的观察接线。
- Android：`RestAlertsBridge.kt` 的通道／声音／诊断上下文，`RestAlertsStore.kt` 的已有领取事实观察，`DiagnosticsContract.kt`、`DiagnosticsStore.kt`、`DiagnosticsRuntime.kt`、`DiagnosticsPackage.kt` 及相关测试；`tool/verify_diagnostics_package.ps1` 更新版本校验。
- 设计依据：沿用 `focus-a-2026-10-14` 与 `diagnostics-ui-2026-10-23` 的 C01–C04、D17/D18、L 系列、INT-10/12/13、REM-01–06、LOGUI-01–12；D19 的三声音选择被本增量明确替代。实施阶段更新当前文字规范和验收说明，历史归档产物保持原样。
- SQLite 保持 v6，完整备份保持 schemaVersion 1；不新增 `sound_id=system`，不更改计划、训练快照、完成／跳过、休息截止、历史统计、备份恢复事务或诊断总开关／清空／保留边界。
- 不新增网络、遥测 SDK 或广泛权限；日志仍本地保存、7 天／20 MiB、主动导出。此次只创建该 change 的规划文件，实施和发布另行启动。
