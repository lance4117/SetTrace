# Design

## Context

动机和产品范围见 `proposal.md`。现有首页位于 `plans_page.dart`，通过 `PlanRepository` 加载计划及按 `sort_order` 排列的动作。计划和动作使用 SQLite 本地自增 ID；会话与历史为独立快照。本次可以只新增计划传输层和批量写入方法，不需要数据库迁移。

项目当前没有文件选择或分享插件，Android `MainActivity` 仅继承 `FlutterActivity`。Android 工程沿用 Flutter 的最低版本；已安装 Flutter SDK 的 `FlutterExtension` 默认值为 API 24，因此设计同时覆盖 API 24–28 和 API 29 以上。现有界面允许计划名 40 个字符、动作名 60 个字符、1–100 组、0–3600 秒休息，休息步进为 30 秒；仓库只有部分下限校验。

## Goals / Non-Goals

**Goals:**
- 将与本地数据库身份无关的计划配置编码为稳定的传输契约，两种导出渠道使用同一内容。
- 隔离文件平台能力，使编解码、预览、导入事务和大部分界面能够用 Dart 测试。
- 明确成功、取消、失败和整批回滚边界，使备份不会依赖应用私有目录。

**Non-Goals:**
- 不复制数据库文件，不导入原设备的主键或数据库版本。
- 不注册文件关联，不添加系统分享面板、自动读剪贴板或后台自动备份。
- 首版不新增通用云存储抽象或面向其他平台的文件导出实现。

## Decisions

### 1. 定义独立的 JSON v1 传输格式

新增无数据库 ID 的传输模型及纯 Dart 编解码器，放在 `lib/features/plans/`。文件扩展名为 `.settrace.json`，编码为 UTF-8，剪贴板使用相同的可读 JSON 文本。推荐编码结构如下：

```json
{
  "format": "settrace.training-plans",
  "schemaVersion": 1,
  "exportedAt": "2026-10-03T08:00:00Z",
  "plans": [
    {
      "name": "练背",
      "exercises": [
        {
          "name": "高位下拉",
          "targetSets": 4,
          "restBetweenSetsSeconds": 120,
          "restAfterExerciseSeconds": 150,
          "defaultWeightKg": 45.0
        }
      ]
    }
  ]
}
```

`format`、`schemaVersion`、`plans` 为必填，`exportedAt` 为可选的 UTC 导出时间元数据，不改变导入后的创建时间。`plans` 的数组顺序为本次导出列表顺序，动作数组顺序即训练顺序；不额外传递 `sortOrder`。重量允许省略或为 `null`，其余动作配置为必填。v1 中未知的附加字段可忽略，但格式标识错误、未知版本和缺失必填字段必须报错，不能靠默认值掩盖损坏内容。

名字去除首尾空白，按现有输入框字符口径限制为计划 1–40、动作 1–60；组数为 1–100 的整数，休息为 0–3600 的整数且为 30 的倍数；重量为有限正数或空。允许动作列表为空，维持现有空计划不可开始的规则。计划数组为空时提示没有可导入的计划。导出也执行相同校验；遇到超出 v1 范围的历史或外部写入值时报告计划与字段，禁止截断名称、夹取参数或生成无法重新导入的备份。

两种渠道均限制为 2 MiB UTF-8 内容。读取文件时按流累计并在超过上限时停止；导出超限时提示减少选择数量。文本允许首尾空白及 UTF-8 BOM，不解析额外聊天说明、Markdown 包裹或任意自然语言计划。

选择 JSON 而不是 SQLite 文件，避免表版本、主键和训练历史耦合；也比只有动作名称的文本更容易保证完整还原。首版不引入压缩或 Base64，减少分享时的阅读和排查成本。

### 2. 导出选择与一致性快照

首页标题旁新增带语义标签的更多菜单，保留“＋ 新建”，菜单内提供“导入计划”和“导出计划”。导出打开独立选择界面，默认全选，可单选、多选、全选或取消全选，显示已选数量；未选中计划时两种导出操作均不可提交。

选择项只携带本地 ID；确认导出时通过仓库在同一只读事务中读取最新的完整计划快照，再编码一次，由用户选用的渠道输出。若有已选择计划被删除，则提示重新选择，不默默漏掉它。导出只读取计划表，不修改计划或会话。复制由 Flutter 的 `Clipboard` 完成，成功后提示“已复制 N 个计划”；不在页面进入或应用启动时读取剪贴板。

与每个计划卡片分别新增分享入口相比，首页统一选择界面同时支持分享一个和备份全部，减少重复界面；快捷单计划入口留待后续。

### 3. 文件默认直接写公共下载目录

新增可注入的 Dart 文件适配器，通过 `MethodChannel` 对接 Android 文件桥接类。核心接口分别为保存到 Downloads 与选择并读取一个文档，返回结构化的成功、取消或错误结果。原生 I/O 在后台执行，结果回到主线程，所有挂起请求只完成一次。首版不新增第三方运行时插件。

- API 29 以上：使用 `MediaStore.Downloads`，`RELATIVE_PATH` 指向 `Environment.DIRECTORY_DOWNLOADS`，MIME 为 `application/json`。通过 `IS_PENDING` 隔离尚未写完的内容，写入并关闭流后才发布；失败时仅删除本次创建的记录。不申请广泛存储访问权限。
- API 24–28：仅为导出申请运行时 `WRITE_EXTERNAL_STORAGE`，清单将其 `maxSdkVersion` 限为 28。使用公共 Downloads 目录，写完临时文件后发布为最终文件，必须防止覆盖已有文件并清理失败产物。拒绝权限时给出失败结果，用户仍可选择复制。
- 文件名由应用生成，如 `训练计划备份-2026-10-03-160000-123.settrace.json`；使用设备本地时间和毫秒，重名时增加序号，不使用计划名称作为路径。两套实现均返回最终实际文件名和“下载”位置。
- 只有文件完整写入并发布后才显示“已保存到下载目录：<文件名>”；下载目录不可用或写入失败时提示错误，不能退回私有目录后仍声称备份成功。

相比系统“另存为”选择器，直接写 Downloads 符合已确认的默认位置需求；相比应用私有 external files 目录，公共目录能在卸载后保留。网盘和其他导出目标不出现在首版操作中。

### 4. 文件导入走系统文档选择，文本导入由用户主动粘贴

文本入口展示可编辑的多行输入框与“粘贴”按钮；用户点击后才读取剪贴板，也可手动粘贴，提交时交给同一编解码器。空剪贴板或无法识别的内容给出可操作的提示。

文件入口使用 `ACTION_OPEN_DOCUMENT`、`CATEGORY_OPENABLE`，选择一个本地文档，由 `ContentResolver` 读取；兼容部分文件管理器把 JSON 标为普通文本或通用文件的情况，最终以内容标识和版本校验，不只依据扩展名。使用返回的 URI 读权限，不把 URI 当作磁盘路径，不申请读取整个存储的权限，也不保留长期 URI 授权。用户取消、空文件、超限、失效 URI 或读取失败都不写数据库。

不增加网盘集成；系统选择器可能自行展示其他已安装文档提供者，应用的离线验收仅依赖本地文件。选择结果或 Activity 重建无法恢复时按取消处理，不能展示旧的导入预览或误提交。

### 5. 预览后一次性新增，名称冲突生成副本

解析后的导入草稿只保存在内存。预览按原顺序展示每个计划、动作数、总组数和可展开的完整动作参数，允许修改各计划名称；首版确认时导入文件内所有计划，选择性导入不在本次范围。

同名检查覆盖当前数据库和本批次已经保留的名称。原名未使用时保留；冲突时依次尝试“练背（导入）”“练背（导入2）”等，按 40 字符上限缩短原名部分，为后缀留足空间。预览显示最终拟用名称；用户改名后再次检查，并生成不冲突的名称，不允许选择覆盖现有计划。

`PlanRepository` 新增批量导入方法，在一个 `db.transaction` 内校验全部草稿、检查名称并写入计划和动作。新计划使用当前创建时间，新动作顺序为连续的 1 起序号，数据库分配新 ID。不能逐次调用已有独立事务的 `createPlan()` 和 `addExercise()` 来拼成批量导入。提交时再次检查预览名称是否发生冲突；如有变化，回到更新后的预览让用户重新确认，本次不写入。任何插入失败都回滚整批。

确认保存期间禁用重复提交；成功后刷新首页并提示导入数量。取消和返回丢弃草稿，错误时保留可重试的预览。原计划、历史记录、正在进行的训练和休息截止时间均不参与更新。

### 6. 验证按契约和真实设备分层

- 纯 Dart：验证 Unicode、空动作列表、可选重量、动作顺序、多个计划、两种渠道的格式一致性、各类非法字段、未知版本和大小边界；验证导出内容再解码能恢复配置。
- SQLite FFI：验证新 ID、同名及批内冲突、预览与提交间的名称冲突、重开数据库后的持久化；注入后续插入失败验证整批回滚，并检查原计划和会话快照。
- Widget 与可替换平台适配器：验证选中数量、空选择、预览改名、取消、重复提交、剪贴板错误、保存失败和成功反馈；复用主题 Token，检查 360–430 dp 与字体放大下主要操作可达。
- Android：分别验证 API 24–28 权限分支和现代 Downloads 分支。使用可丢弃的测试设备导出文件、卸载、重装、从下载目录选择并导入；逐字段核对恢复结果，并记录拒绝权限、写入失败和文件选择取消结果。

## Risks / Trade-offs

- [导出路径误用应用私有目录，卸载后文件丢失] → 明确两套公共目录实现，必须用卸载重装验收，不能只检查文件存在。
- [v1 参数上限比仓库校验严格] → 上限沿用正常编辑界面，导出预先报告无法表示的数据，不做静默转换；后续扩大范围必须同步格式契约与编辑界面。
- [批量保存失败或名称在预览后被占用] → 事务重新校验并整体回滚，冲突时返回预览，不自动覆盖。
- [大文件或不兼容分享文本造成解析问题] → 统一 2 MiB 上限、流式限量读取和明确格式错误；界面只展示可理解的错误，不泄露原生堆栈。
- [旧 Android 用户拒绝存储权限] → 仅在实际文件导出时请求，提供重试或剪贴板方式，不要求改变导出目录。
- [计划文件被误认为包含训练历史的完整备份] → 导出选择与成功提示使用“训练计划备份”，说明包含计划配置，README 同步说明。

## Migration Plan

1. 保持当前数据库版本与既有表结构，新增纯 Dart 传输能力、仓库批量导入和 Android 文件桥接。
2. 接入首页入口与选择、预览界面，通过格式、数据库及界面测试后进行两类 Android 分支验收。
3. 用可丢弃的测试设备完成卸载重装恢复验收，再更新 README 和验收记录。
4. 如需回退功能，可关闭入口或回退界面与桥接代码；已经导入的计划仍是现有表中的普通计划，下载文件继续保留，不删库或删除用户备份。
