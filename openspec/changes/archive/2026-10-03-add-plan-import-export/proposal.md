# Proposal

## Why

训练计划目前仅保存在设备上的 SQLite 中，用户无法把完整计划分享给别人，也无法在卸载或清除应用数据前保留一份可恢复的备份。在首页增加计划导入导出，让用户通过文本分享计划，并把计划文件保存到系统公共下载目录，之后可以重新导入。

## What Changes

- 在首页“训练计划”标题旁增加更多菜单，提供“导入计划”和“导出计划”，保留现有新建入口。
- 导出支持选择一个或多个计划、全选；提供“复制到剪贴板”和“导出到文件”两种方式。
- 两种方式共用带格式标识和版本号的 JSON，完整保留计划名称、动作名称及顺序、默认组数、组间休息、动作完成后休息和可选默认重量。
- 文件默认直接保存到 Android 系统公共下载目录，文件名带日期、时间并处理重名；保存成功后展示实际文件名和位置。导出文件在卸载应用后仍保留。
- 导入支持用户主动粘贴计划文本或选择本地文件，先校验和预览，再确认保存；预览展示计划和动作配置，并允许修改待导入的计划名称。
- 导入创建新的计划和动作，同名计划默认生成带“（导入）”后缀的名称；整批导入使用事务，校验或保存失败不留下部分计划。
- 首版范围为训练计划配置；历史记录、正在进行的训练、主题设置、云同步、网盘保存和自定义导出目录不在本次范围内。

本提案采用前序讨论中的“单选、多选、全选”和“同名创建副本”作为设计默认值；明确确认的文件保存目标为公共下载目录。

## Capabilities

### New Capabilities

无。扩展现有计划管理及应用体验能力。

### Modified Capabilities

- `training-plans`：增加完整计划的可移植格式、选择导出、剪贴板与下载文件导出、文本与文件导入、同名副本及原子保存要求。
- `app-experience`：增加首页导入导出入口、选择与预览流程、保存结果反馈及离线可用的交互要求。

## Impact

- Flutter 计划模块：`lib/features/plans/plans_page.dart`、`plan_repository.dart`，以及新增的传输数据模型、编解码、导入预览与导出选择界面。
- Android 平台：增加文件导出和本地文件读取的 Flutter 平台通道；现代 Android 使用公共 Downloads 存储接口，兼容旧版本时仅申请所需的写入权限。
- 数据层：复用 `plans` 和 `plan_exercises`，导入时分配本地新 ID，不迁移或替换数据库；训练会话与历史继续使用各自独立的快照。
- 验证与文档：补充格式往返、导入回滚、同名处理、交互反馈测试，以及下载文件在卸载重装后可恢复的 Android 验收记录；更新 README 的功能及数据备份范围。
- 运行范围仍以 Android 为交付目标，核心导入导出不需要账号、网络或服务端。
