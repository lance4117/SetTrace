# Proposal

## Why

SetTrace 当前界面和部分原生文件操作提示仅支持中文，英文用户无法获得完整、自然的使用体验。需要一次建立轻量的国际化机制，使完整英文支持和后续仅添加语言包即可扩展语言成为同一套能力，并用检查避免文案遗漏。

## What Changes

- 使用 Flutter 官方 `flutter_localizations`、`gen-l10n` 与 ARB 语言包，英文为基准语言，首版提供英文和简体中文；只考虑从左往右的语言。
- 设置页在外观下增加语言单选，依次显示 `English`、`中文`，名称始终使用该语言的自称。可选语言由生成的语言包清单派生，后续新增完整 ARB 包并正常生成、构建即可接入，无需修改业务页面或手工登记语言。
- 无保存偏好时按系统首选语言选择：中文进入中文，其他未支持语言或检测失败进入英文；选择立即生效并本机保存，不增加“跟随系统”选项。
- 全量处理页面、导航、弹窗、错误与成功提示、占位符、无障碍文字，以及动态数量、复数、日期、时长和数字格式；英文按健身应用语境撰写和审阅。
- 业务层和 Android 文件桥接返回稳定的错误代码、参数及目录标识，显示层统一翻译；导入重名后缀按当前语言生成并保留原有冲突确认和事务规则。
- Android 桌面名称及应用标题固定为 `SetTrace`；备份文件使用固定品牌前缀、保留时间戳和扩展名。
- 加入资源完整性、参数一致性、硬编码文案检查，以及中英文流程和加长文案布局验收；运行时英文兜底不代替发布前翻译完整性检查。
- 用户名称、历史快照、数据库与计划 JSON v1 格式、kg 单位、训练计时及统计规则保持稳定，不做数据库迁移。

## Capabilities

### New Capabilities

- `app-localization`: 语言包扩展、系统语言解析、手动切换与持久化、完整本地化呈现、固定品牌名称以及翻译和布局质量检查。

### Modified Capabilities

- `training-plans`: 将“确认后原子新增计划副本”中的固定中文重名后缀改为按当前应用语言生成，保持名称长度、预览确认、重新冲突检查与整批回滚约束。

## Impact

- Flutter：`pubspec.yaml`、新增本地化配置及 ARB 资源、`lib/app/app.dart`、设置页、所有功能页面和共享组件、日期和数量显示辅助函数。
- 计划传输：`plan_transfer.dart`、`plan_repository.dart`、`plan_transfer_platform.dart`、导入导出页面，以及 Android `PlanFilesBridge.kt` 的内部返回协议；客户端和原生桥接须在同一 APK 同步更新。
- Android：`AndroidManifest.xml` 的应用名称、备份文件品牌前缀；不更改包名、应用 ID 或存储路径。
- 验证与文档：现有 widget、导入导出和仓库测试，新增轻量本地化检查和测试，语言包添加说明与验收记录。
- 范围不含 RTL、在线翻译、远程语言包、地区／单位切换、系统级应用语言设置接入、用户内容翻译或自研翻译框架。
