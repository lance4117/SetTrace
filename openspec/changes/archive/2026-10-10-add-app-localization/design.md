# Design

## Context

动机见 `proposal.md`。当前 `pubspec.yaml` 没有本地化依赖，`MaterialApp` 没有语言配置；`SetTraceApp` 已用 SharedPreferences 保存主题，可直接扩展语言偏好。页面、组件及历史时长辅助函数硬编码中文，现有 widget 测试也依赖这些中文文字。

计划校验会拼接中文的计划序号、动作序号与字段名称；`PlanTransferException` 只有显示用 message。Android 文件桥接返回中文 message 和目录文字，Dart 还用 `location == '下载'` 判断保存结果。重名规则在 `resolveImportNames` 中，并同时用于预览与保存前再次校验。Android Manifest 的应用名称是“训练本”。现有规范要求公共下载备份、JSON v1 往返兼容、名称长度限制、冲突重新确认和事务回滚，均须保留。

本变更跨页面、共享组件、仓库及原生桥接，并新增官方依赖，故需要设计文档。现有 app-experience 规格中中文功能名称保留其语义，在英文界面使用对应译文，导航和操作能力不改变。

## Goals / Non-Goals

**Goals:**

- 一套生成的强类型文案接口；所有支持语言及设置列表只从语言包派生。
- 业务只处理数据和稳定标识，显示层负责语言；按需增加少量格式化辅助函数。
- 用现有应用状态和偏好存储完成切换，不引入状态管理框架、数据库表或服务。
- 资源完整性检查可重复执行，英文准确性和界面覆盖通过有上下文的验收确认。

**Non-Goals:**

- 自研国际化框架、插件注册系统、在线／热更新语言包、翻译后台、RTL、单位与地区设置。
- 接管 Android 系统文件选择器、权限窗口等系统拥有的文案；它们继续遵循系统设置。应用生成的提示统一遵循应用语言。
- 系统设置中的每应用语言入口，以及让桌面名称随语言变化。

## Decisions

### 1. 官方 ARB 和生成清单是唯一语言来源

使用 SDK 的 `flutter_localizations`、匹配 Flutter SDK 的 `intl`、`flutter gen-l10n`，新增 `l10n.yaml` 和 `lib/l10n/app_en.arb`、`app_zh.arb`。英文为模板与最终回退；简体资源使用通用 `zh`，首版所有中文系统语言落到现有简体中文。

各包包含 `@@locale` 和 `languageSelfName`（`English`、`中文`），其余键与英文模板保持一致。模板提供文案上下文、占位符说明和类型。设置遍历生成的 supportedLocales，使用该 locale 对应资源的自称，固定 en、zh 优先，其余按语言标签稳定排序；不维护第二份语言枚举或注册表。所有包随 APK 发布、离线加载。

新增官方本地化数据已覆盖的 LTR 语言时，添加完整 `app_<locale>.arb` 后执行同一套检查、生成和构建即可。生成清单、设置选项、标准日期数字格式与语言匹配一起扩展；不要求改页面、原生资源或校验脚本。语言包是构建时资源，不承诺运行时拖入文件即时加载。

选择官方机制是为了复用 ICU、复数和标准组件翻译。排除手写 Map、页面里的语言分支、第三方国际化框架和额外注册机制。

### 2. 根应用状态持有一个语言偏好

在现有根状态中增加 locale，使用 SharedPreferences 的单独键保存 BCP 47 语言标签。启动前读取偏好、匹配生成清单并完成语言初始化，避免首页先闪现中文。

没有保存偏好时只匹配系统当前首选语言：优先准确标签，再按框架标准匹配同语言的兼容变体；无匹配、系统语言不可读或已保存的标签无效时回退英文。不遍历第二偏好去选择中文，未支持的法语首选即使后面有中文也进入英文。首次解析结果持久化，之后系统语言变化不覆盖选择。无偏好的旧版本升级也采用这一规则，不增加识别旧用户的机制。

用户切换时先完成偏好保存，再更新根 locale；保存失败保留原选择并显示当前语言下的可理解错误。`MaterialApp` 使用生成清单和官方 delegates。重建时保持 Navigator、当前 tab、编辑草稿、数据库仓库和训练会话的身份，不通过更换根 key 或重新 runApp 切换。缓存的错误保持代码和参数，渲染时按当前 locale 生成文字，避免切换后继续显示旧语言。新打开的页面、菜单和对话框自然继承 locale；已有仍展示的应用文案也应刷新。

语言选项只有已发布语言，不提供“跟随系统”。这比自动跟随加手动覆盖的三态偏好简单，也符合首次检测的使用方式。

### 3. 句子、数量和格式按语义本地化

每条动态消息作为完整资源，用有类型的占位符和 ICU plural/select 表达，不拼接翻译片段。英文将 Workout 用于一场训练、Exercise 用于动作、Set 用于组、Rest 用于休息、History 用于历史入口；结束、保存与放弃须明确表达实际结果。翻译备注明确次数、已完成／目标组数、组间／动作间休息等语义。

日期、月份、时间和数值使用当前应用 locale 的标准格式，必要的日期数据按 locale 初始化，不建立手写语言格式表。时长用完整带复数的资源或短格式，倒计时继续显示固定 `mm:ss`。休息调整仍为 30 秒、重量仍为 kg、历史的周起点及设备本地日期规则不变。

重量输入统一采用不接受分组符号的简单规则：允许数字及单个小数点或逗号作为小数分隔，不允许混合、重复分隔符或非有限数；按当前语言展示示例和已有值，输入提交解析成相同数值。源代码里已有的逗号转小数点兼容保留，但明确拒绝歧义输入。数据库和导出 JSON 的数值、秒数、UTC 时间戳均不本地化。

### 4. 文件和业务错误从显示文字改为结构化数据

使用小型错误类型／枚举加参数，覆盖当前已存在的校验和平台失败原因，不建设通用异常框架。校验定位携带计划序号、动作序号、字段代码、上下限或用户名称，禁止在业务层先拼中文 path；UI 由资源生成完整定位信息。未识别代码显示当前语言的通用失败提示，不直接展示平台 message、堆栈或 `$error`。

`PlanFilesBridge.kt` 与 Dart 同时更新：保留 success/cancelled/error 状态及真实结果，错误返回稳定 code 和必要参数，成功位置返回 `downloads`。真实 fileName 原样呈现，目录显示标签交由 Flutter 翻译。公共下载位置校验、清理失败输出、旧 Android 权限路径和拒绝重复提交规则保留。

桌面名称及 `MaterialApp.title` 固定 `SetTrace`；原生备份名采用 `SetTrace-plans-<timestamp>.settrace.json`，保留本地日期时间和重名避让。品牌和固定协议常量是允许的不可翻译文字，无需为每种语言增加 Android 资源文件。

### 5. 导入重名策略作为一个小型格式化回调传入

将后缀格式化作为必要参数传给预览、名称解析及事务内重名复核，不把 BuildContext 或本地化类注入仓库。中文保持 `（导入）`、`（导入2）`；英文使用 ` (imported)`、` (imported 2)`，未来由新包提供同一资源的译文。

一次导入预览和提交使用同一语言的后缀格式化规则；如预览重新计算则明确展示新拟用名称并等待确认，不静默改名保存。继续按 grapheme 保留 40 字符总上限、完整后缀和可用原名；译文检查保证后缀为非空且留下原名空间。与现有／批内名称冲突的比较仍是完整名称比较，不依赖识别或剥离中文后缀。保存后名称成为用户数据，切换语言不再改写。

这是现有 training-plans 规格的实际行为变更，必须通过增量规格替换固定中文要求，其余原子新增约束保留。

### 6. 质量检查保持小而明确

增加一个 Dart 可执行检查入口（例如 `dart run tool/check_localizations.dart`），自动发现所有正式 ARB 包并核对：非空文本、键集相同、locale／自称有效且唯一、占位符名称和类型一致、后缀长度可用。ICU 语法和复数结构交给 gen-l10n 验证，各语言允许不同复数类别，不要求复制英文的类别。生成器的缺译报告必须为空，不能把英文默认填充当成完成翻译。

同一入口对应用文字出口及相关 Dart/Kotlin 文件执行轻量硬编码检查，覆盖文字控件、提示、无障碍、用户错误和动态拼接。对协议键、品牌、日志等明确列出有限的例外和原因；不使用“扫描中文字符”作为唯一方式，也不排除整个业务文件。源文件检查不宣称能证明语义正确，配合按页面和失败路径记录的人工文案清单。仓库目前没有 CI 配置，本变更提供一个本地／未来 CI 均可调用的命令并写入发布检查说明，不额外建设 CI 平台。

新增完整第三语言的测试在临时资源副本中运行生成流程，验证设置自动出现、locale 匹配和格式化生效，无需修改清单或 resolver；测试资源不进入正式包。加长文案使用测试 delegate／fixture，验证 360–430 dp、大字体和深浅主题，不增加生产语言。中英文覆盖全部用户流程及已知错误类别，英文完成语境和术语审阅后才能标记验收通过。

## Risks / Trade-offs

- [跨层错误转换漏掉原生或缓存消息] → 按 Dart 校验、仓库、原生桥接与页面出口分别建立清单，验证同一错误在中英文下的可读定位和重试路径。
- [语言包完整却翻译生硬或改变操作含义] → 模板提供上下文和术语备注，人工检查关键操作及参数意义；自动检查只证明结构，不代替语言审阅。
- [长译文或大字体使操作不可达] → 为行、按钮、标题提供正常换行／弹性空间，使用加长文案和小屏验收，保留至少 48×48 dp 点击区域。
- [保存语言或切换重建损坏草稿／训练进度] → 偏好保存失败不切换，沿用根状态身份，验证 tab、草稿、训练完成组及休息截止时间没有重置。
- [无偏好旧用户在英文系统上升级后改为英文] → 明确采用统一首次解析规则，并在发布说明告知可随时在设置切回中文，不增加迁移分支。
- [本地化名称后缀破坏重名处理或长度限制] → 同一格式化策略用于预览与事务复核，复用 grapheme 截断和批内冲突测试，存量名称不迁移。
- [Flutter locale 数据不支持任意语言] → 语言包添加承诺限定在官方格式化和控件本地化已覆盖的 LTR 语言；新语言使用同一完整性及验收流程。

## Migration Plan

1. 同一变更内加入语言资源与生成配置，接入 locale 状态，逐模块迁移文案和格式化；所有正式语言资源完整后才发布。
2. 同一个 APK 同步更新 Dart／Kotlin 错误协议和目录标识，变更桌面名和新备份名；旧 JSON 和旧文件名仍能正常导入。
3. 更新现有测试的本地化环境和结构化错误断言，运行资源检查、gen-l10n、analyze、测试和 Android 构建，再完成文案与设备验收。
4. 不升级数据库版本，不改包名、实时存储路径或 JSON v1。不重命名旧下载备份，不重写历史数据。新增偏好键对旧版无影响；代码回退时 Dart 和原生须一起回退，已有计划、历史及备份仍可读。
